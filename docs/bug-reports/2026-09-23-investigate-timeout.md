# 调查进入多人投入窗口时循环超时

- 游戏：`85ad926c-9249-4a2e-931c-44404bd0dcb1`
- 现场：午夜假面，存档 step 243，黛西·沃克的回合，点击基础“调查”。
- 错误：`RunMessagesTimeout (...) 30000000`，即消息处理超过 30 秒。

## 复现与根因

只读导出现场存档，用 `arkham-replay` 提交对应调查选项（索引 9）。
技能检定生成 `AskMap`：黛西拥有投入卡牌和开始检定按钮；同地点的佐伊只有一个可投入卡牌选项。

`soleRequiredTarget` 原先仅按选项数量和 `TargetLabel` 外形判断是否应自动执行。
它把佐伊的单张可投入卡当成必选目标，执行 `SkillTestCommitCard`。
重新生成窗口后，佐伊唯一的选项变成取消投入，又被自动执行 `SkillTestUncommitCard`。
这两个操作持续互相触发，无法停在等待玩家输入的窗口。
中止修复前重放时，日志已各记录 474 次投入和取消投入。

超时异常在数据库事务内部抛出；该次操作回滚。延长超时时间无法解决循环。

## 修复

`soleRequiredTarget` 排除包含 `SkillTestCommitCard` 或 `SkillTestUncommitCard` 的选择，
包括 `Run` 和 `Do` 包装的消息。单张投入/取消投入仍交给玩家决定；普通唯一必选目标继续自动处理。

## 验证

- 修复前：真实存档离线重放已复现循环。
- 回归测试覆盖唯一投入、唯一取消投入、包装消息，以及普通必选目标。
- 修复后的编译、回归测试与同存档重放结果待填写。
