## 1. 设计目标与核心体验

### 1.1 主题概念

玩家打开界面，像走进一间深夜仍亮着台灯的调查室。桌上有案件卷宗、调查员照片、地图、卡牌和尚未解释的符号。进入游戏后，档案室自然过渡为一张可操作的调查牌桌。

台灯照亮的纸张和桌面是主要使用区域。夜色保留在场景插画与外围，不把整个应用压成深绿色。“午夜”描述故事氛围，不要求低亮度界面。

核心气质：沉静、考究、古旧、略显不安。卡牌鲜明，工具克制，恐惧在关键时刻浮现。

三种诉求各自承担明确职责：

| 诉求 | 来源 | 对界面的要求 |
| --- | --- | --- |
| 克苏鲁氛围 | 未知、尺度失衡、理性受到侵蚀 | 环境留白、局部异常、剧情揭示节奏 |
| 桌游质感 | 卡牌、标记、桌垫、卷宗等物件 | 稳定空间关系、真实比例、触感反馈 |
| 精致 UI | 排版、层级、对齐与一致性 | 清晰操作、细边、克制配色、完整状态 |

### 1.2 设计原则

1. 日常操作保持理性，剧情时刻允许异常。
2. 当前任务优先于环境装饰，玩家随时知道轮到谁、可以做什么。
3. 中文拥有完整字体和排版体系，不能依赖西文装饰字体的偶然回退。
4. 保留游戏既有职业、技能、标记与卡面语义。
5. 氛围通过整体构图、材质、光线和留白建立；触手和符文只在有意义的位置出现。
6. 高频页面适合连续使用两小时，避免持续闪烁、抖动和全屏特效。
7. 同一组件在不同页面拥有相同的状态、尺寸与操作规律。
8. 默认界面使用明亮内容面板，区域在灰度模式下也能辨认；不以深黑绿背景表达恐怖氛围。

### 1.3 三种界面模式

| 模式 | 页面 | 氛围强度 | 信息密度 |
| --- | --- | --- | --- |
| 档案浏览 | 首页、战役选择、日志、成就 | 中至高 | 中 |
| 精密工作台 | 卡牌库、牌组编辑、设置、管理工具 | 低至中 | 高 |
| 调查牌桌 | 游戏、观战、回放 | 环境低、关键事件高 | 随游戏变化 |

模式共享字体、控件、间距与状态，只改变表面材质和背景表现。

### 2.2 现状问题与目标

| 当前模式 | 目标 |
| --- | --- |
| 深黑绿底面明度接近，区域容易融合 | 暖灰页面、亮纸面、中灰牌桌，明确分开承载层 |
| 面板普遍拥有明显轮廓和硬阴影 | 明度差与细实线建立边界，接触阴影辅助分层 |
| 亮绿按钮与描边权重较高 | 深孔雀绿主操作、黄铜局部强调 |
| 标题偏粗重，西文字体种类多 | 中文宋体标题、黑体工具文字、少量档案编号字体 |
| 全局规则与页面 scoped 样式混用 | token → 基础组件 → 领域组件 → 页面编排 |
| 部分页面硬编码颜色 | 所有通用状态归入语义变量 |

### 2.3 约束

- 视觉改造不得改变行动合法性、阶段推进、卡牌结算、隐藏信息或随机结果。
- 不将观战、回放或管理身份的权限判断移入视觉组件。
- 保留现有翻译资源、卡图、游戏图标和有效路由。
- `/new-game` 与 `/campaigns/new` 当前均存在，设计统一体验，实施时确认各自调用方并保持链接兼容。
- `/admin/rooms` 是管理页面，不能直接改成面向所有玩家的公共房间大厅。
- 本文提出的新交互如持久化布局偏好、日志筛选，应先确认现有能力；需要新增数据或接口时单独列出依赖。
- 工作区已有其他修改，后续实现必须先确认文件状态，不覆盖并行工作。

## 3. 美术指导

### 3.1 三层世界

| 层次 | 元素 | 应用 |
| --- | --- | --- |
| 人类的秩序 | 编号、档案标签、打字记录、索引、照片 | 导航、列表、表单、日志 |
| 年代与物件 | 旧纸、布面、皮革、氧化黄铜 | 卡槽、面板、封面、桌面 |
| 未知的侵入 | 不完整符号、远处轮廓、微光、局部失衡 | 场景边缘、剧情和关键事件 |

普通页面建议视觉面积分配：70% 暖灰及明亮纸面，20% 卡牌与档案内容，8% 导航、结构及身份色，2% 异样强调。游戏页面以中灰桌面和原色卡牌为主，纸面侧栏提供明确边界。比例是构图指导，不是程序按像素计算的要求。

### 3.2 光线

- 统一左上方暖光与偏冷环境光。
- 可操作区域保持充分照明，不叠加全屏暗角、绿色蒙层或降低整体亮度。
- 桌面中央保持安静，场景细节集中于边缘。
- 主体卡牌不叠加统一绿色滤镜，不降低原始插画可读性。
- 重要剧情可以改变外围环境光，不能遮住规则和按钮。
- 文字面板不使用复杂背景透射，避免玻璃效果干扰长文阅读。

### 3.3 装饰尺度

- 主标题可有一组角饰或一条带符号的分隔线。
- 每个普通面板不再重复配置完整花边。
- 磨损集中于边缘，正文区域干净。
- 印章用于归档、结局或章节性质，不代替交互状态。
- 避免无处不在的骷髅、滴血、尖刺、触手，以及高饱和紫绿渐变。

### 4.1.1 边界与明度规则

- 页面背景、面板、输入区域分别使用暖灰、纸白、亮纸白，避免连续嵌套多个近似深色表面。
- 面板之间至少保持 16px 间距；确需紧凑布局时，以清楚实线分隔。
- 纸面面板使用 1px 结构边框；输入框使用独立控件边框。装饰分隔线不能代替必要的控件边界。
- 游戏的中灰桌面与两侧纸面信息栏形成明确明度差；小型深色卡牌采用浅色卡槽或浅色外轮廓辅助辨认。
- 在灰度截图以及关闭纹理、阴影的条件下，仍应能辨认导航、主内容、侧栏、输入框和主要操作。
- 游戏桌面不直接排长段反白文字，规则和日志放到明亮面板内。
- 本版本不以深黑绿主题作为默认或后备样式；如未来增加暗色模式，需单独完成边界与对比度验证。

### 4.2 游戏色与交互色分离

保留当前职业、技能、生命、理智和混乱标记变量的语义。初期优先保留已有颜色，再通过背景和边框改善协调性。

| 状态 | 表现 | 必须有的非颜色信息 |
| --- | --- | --- |
| 可操作 | 深青角标配浅色衬底 | 动作名称或可操作标识 |
| 已选择 | 黄铜轮廓、轻微抬起 | 勾选和已选择状态 |
| 键盘焦点 | 外侧连续焦点环 | 稳定焦点位置 |
| 危险／错误 | 干血红或错误文字色 | 图标、原因和处理方式 |
| 禁用 | 降低表面强调 | 原因说明，不能仅降低透明度 |
| 等待其他玩家 | 静态状态签 | 玩家名称与等待事项 |

职业紫不能作为唯一选中信号；生命、理智、诅咒等规则属性也不能随场景主题换色。

### 4.3 字体

推荐中文标题采用思源宋体或 Noto Serif CJK SC 方向，功能正文采用思源黑体或 Noto Sans CJK SC 方向。实际字体文件、授权与覆盖范围在资产准备时确认，项目当前已有 Noto Sans 名称不等于已验证完整中文字形。

| 内容 | 字体类别 | 桌面规格 | 手机规格 |
| --- | --- | --- | --- |
| 页面标题 | 宋体 | 32/44px，600 | 26/36px，600 |
| 区块标题 | 宋体 | 22/32px，600 | 20/30px，600 |
| 正文 | 黑体 | 16/26px，400 | 16/26px，400 |
| 工具栏／按钮 | 黑体 | 14/20px，500–600 | 14/20px，500–600 |
| 剧情 | 宋体 | 18/32px，400 | 17/30px，400 |
| 辅助信息 | 黑体 | 13/20px | 13/20px |
| 编号／数值 | 清晰等宽或等宽数字 | 12–14px | 12–14px |

规格中的 `32/44px` 表示字号／行高。关键规则不能降为 12px 辅助字。

- 中文标题字距建议 0.02–0.06em，正文保持正常字距。
- 英文小栏目可用大写和 0.08–0.12em 字距。
- 同屏主导字体不超过三类，图标字体不计入正文体系。
- 手写体仅用于短批注，不用于规则和按钮。
- 数值使用等宽数字，资源变化不造成布局跳动。
- `ArkhamIcons`、`ArkhamEncounters` 等保留专用用途，不参与中文正文回退。

### 4.4 间距、圆角和宽度

| 类别 | 规格 |
| --- | --- |
| 间距阶梯 | 4、8、12、16、24、32、48、64px |
| 常规控件高度 | 40px；触控环境最小目标 44px |
| 紧凑桌面控件 | 32px，图标操作需补足实际命中区域 |
| 控件圆角 | 3–4px |
| 面板圆角 | 4–6px |
| 模态圆角 | 6–8px |
| 描边 | 常规 1px，焦点环独立 |
| 标准页面最大宽度 | 1280px，宽屏内容可扩展至 1440px |
| 长文阅读宽度 | 约 36–42 个汉字，随字号适配 |
| 页面边距 | 桌面 32px，平板 24px，手机 16px |

圆形用于标记、必要头像或状态点；普通标签避免全部胶囊化。

## 5. 材质与表面

### 5.1 四种基础材质

| 材质 | 场景 | 细节 |
| --- | --- | --- |
| 石墨构件 | 导航、少量紧凑全局工具栏 | 深石墨纯色、清楚反白字，与主体纸面分开 |
| 档案纸 | 默认面板、筛选、表单、剧情、日志 | 明亮暖纸、稀疏纤维、边缘轻磨损 |
| 中灰桌垫 | 游戏中央 | 石板灰低对比布纹，边缘与卡槽清楚 |
| 氧化黄铜 | 索引、关键边角 | 暗金底、窄高光、轻暗部 |

### 5.2 阴影层级

1. 贴面：明度差和细实线，适用于工具区；不依赖内阴影区分区域。
2. 物件：卡牌和照片的短距离接触阴影。
3. 浮层：弹窗和抬起卡牌的柔和环境阴影。

阴影初始候选：接触阴影 `0 2px 4px rgb(35 39 37 / 16%)`，浮层阴影 `0 12px 32px rgb(35 39 37 / 24%)`。阴影只辅助物件层次，边界首先由表面与细实线建立。需按实际卡牌尺寸调整，禁止简单用同一大阴影覆盖所有组件。

纹理作为独立背景层，不与文字共同降低透明度；装饰层不接收鼠标事件，也不进入辅助技术阅读顺序。

## 6. 导航与应用框架

### 6.1 全局导航

桌面主导航：游戏／牌组／卡牌／成就。战役日志从当前游戏进入；账户菜单包含设置、关于与退出。管理员入口仅对相应角色展示。

顶部高度建议 56px。品牌区采用小型符号、宋体中文名称和可选英文副标。活动项使用黄铜短线或档案页签连接，不使用粗大实心亮绿块。

导航使用深石墨底和反白字；其下页面使用暖灰底、纸白面板和深墨字。深色不延伸成整个页面背景，筛选栏和一般工具区保持明亮。

游戏页面进入紧凑导航模式，优先显示剧本、当前阶段、连接状态和菜单。退出游戏页面不应误触结束游戏。

### 6.2 页面骨架

- `ArchiveShell`：档案浏览，暖灰背景、纸白内容，标准宽度，可包含局部场景横幅。
- `WorkbenchShell`：卡牌与工具，明亮筛选和编辑面板，利用屏幕宽度，工具栏可固定。
- `TabletopShell`：游戏，中灰地图、纸白侧栏与手牌承载区，局部滚动和缩放，避免整页随手牌挤动。

这些是建议组件名。现有路由组件继续承担数据加载与业务编排，先抽取重复视觉职责，再决定是否引入独立 Shell。

### 6.3 滚动规则

- 普通页面优先一个主纵向滚动容器。
- 多栏工作台允许独立列表滚动，但列标题保持可见。
- 游戏只对地图、手牌或详情区域使用局部滚动，边界清楚。
- 弹窗打开时阻止背景滚动，关闭后恢复原位置。
- 页面间保留适当的列表筛选与返回位置，不保留过期的游戏行动状态。

## 7. 档案浏览页面

### 7.1 首页：当前调查

对应 `frontend/src/views/Home.vue`，复用 `GameRow.vue`、`EventRow.vue` 的业务数据。

首屏目标：玩家迅速找到当前游戏并继续。

```text
┌─────────────────────────────────────────────────────┐
│ 品牌       游戏  牌组  卡牌  成就             账户    │
├─────────────────────────────────────────────────────┤
│ 当前调查                          导入存档  创建战役 │
│ 简短氛围副文案                                      │
├─────────────────────────────────────────────────────┤
│ 场景照片 │ 战役名称／当前剧本           继续游戏      │
│          │ 调查员、状态、更新时间                    │
├─────────────────────────────────────────────────────┤
│ 其他进行中的调查／多人活动                           │
├─────────────────────────────────────────────────────┤
│ 已归档战役：可折叠列表                               │
└─────────────────────────────────────────────────────┘
```

- 已登录首页的横幅不超过首屏高度约四分之一。
- 列表区域使用暖灰底，每张战役档案卡使用纸白底和 1px 实线边界；夜景只在横幅或照片中出现。
- 当前案件条目高度建议 140–180px；普通条目更紧凑。
- 战役照片保持固定比例，可裁切环境图，不能裁掉关键人物识别。
- 名称支持两行，完整名称可在详情中读取。
- 删除放入更多菜单，不与继续游戏并列争抢注意力。
- 游戏和多人活动使用可辨识的类型标签，保持入口差异。
- 无游戏时显示空卷宗线稿、说明和创建按钮，导入仍可见。
- 加载失败与真正无游戏使用不同状态，失败提供重试。

### 7.2 创建战役：建立卷宗

对应 `NewCampaign.vue`，统一两个已有入口的视觉。

三步结构：选择战役／剧本 → 规则配置 → 调查员与牌组准备。

- 第一步以封面和场景信息建立氛围；支持现有内容分类。
- 第二步用清楚表单呈现难度、模式和已有规则选项，摘要侧栏持续显示。
- 第三步展示调查员、牌组及当前可确认状态；具体顺序遵循现有创建流程约束。
- 前进前验证本步；返回保留已输入数据。
- 确认按钮显示正在创建并防止重复提交。
- 失败保留配置并提供重试，不要求重新填写。
- 自定义内容明确标注，不通过降低对比度表示“非官方”。

### 7.3 加入游戏与认领席位

对应 `JoinGame.vue`、`ClaimSeat.vue`。

- 顶部显示游戏名称、剧本和加入目标。
- 席位采用人物档案卡：照片、玩家名称、调查员及占用状态。
- 区分空席、已占用、本人席位、当前不可加入。
- 席位选择、牌组配置与最终加入按现有业务步骤组织。
- 链接失效、游戏不存在、席位被占用分别解释。
- 提交后以服务端状态确定加入成功；席位竞争失败时刷新可用选项。

### 7.4 战役日志

对应视图与领域组件 `CampaignLog.vue`。

- 宽屏左侧目录约 200px，中间纸面正文，右侧可选摘要约 240px。
- 正文使用亮纸面和深墨字，目录与摘要通过细实线和间距分开，不回到黑绿侧栏。
- 小屏目录变为章节选择器，正文单列。
- 记录保留原有规则语义、顺序和结构，装饰不混入数据。
- 重要结果使用标题、细线和记录框，少量印章表达归档性质。
- 未揭示内容不预加载为可阅读内容，也不通过标题、缩略图或计数泄漏结果。
- 长记录有章节锚点和返回目录入口；读到的位置在合理范围内保留。

### 7.5 成就与关于

- 成就采用收藏册网格，徽章使用低饱和金属或压印质感。
- 已获得与未获得用状态文字、日期和轮廓区分，不只改变颜色。
- 隐藏成就按现有规则控制提示，不能展示剧透插画。
- 关于页采用可读文章布局，清楚列出已有项目说明与资源归属。

## 8. 卡牌与工具页面

### 8.1 卡牌库

对应 `Cards.vue`、`CardListView.vue`、`CardImageView.vue`、`CardDetailsModal.vue`。

```text
┌──────────────────────────────────────────────────────┐
│ 卡牌目录      搜索                     结果数  视图   │
├──────────────┬───────────────────────────────────────┤
│ 职业／类型   │ 活动筛选条件                         │
│ 费用／等级   │                                       │
│ 系列等现有项 │ 卡图网格 或 紧凑列表                 │
│ 清空筛选     │                                       │
└──────────────┴───────────────────────────────────────┘
```

- 桌面筛选栏建议 220–260px；手机变为带结果数的筛选抽屉。
- 搜索与筛选是功能主角，背景只保留低对比材质。
- 筛选和结果区采用纸白面板，输入框使用更亮纸白与清楚边框；职业色在标签和图标中保留。
- 卡图保持比例；列表提供名称、职业、类型及现有关键字段。
- 条件标签支持逐个移除，清空筛选容易找到。
- 零结果明确显示当前条件，可清除条件恢复。
- 搜索结果更新保持布局稳定，不闪回顶部；异步旧请求不能覆盖新查询。
- 加载大量卡图时分批呈现；必要时评估虚拟列表，避免一开始无依据重写。
- 图片失败展示卡名、编号及可获得的规则文字。
- 卡牌详情宽屏大图与文字并排，手机切换／纵向排列，文字可选取。

### 8.2 牌组列表

对应 `Decks.vue`。

- 每个条目显示名称、调查员、职业标记和现有版本／更新时间信息。
- 主操作为打开牌组；导入、新建与现有其他能力进入统一工具栏。
- 牌组封面使用人物档案照片，不将每个条目做成大幅海报。
- 如果当前数据不提供合法性或同步状态，不制造看似真实的状态标签。

### 8.3 牌组编辑

对应 `Deck.vue`。

桌面结构：卡牌筛选／检索 → 可选卡牌 → 当前牌组及统计。宽度不足时筛选收纳，牌组面板仍容易切换。

- 调查员、牌组名称和保存／同步状态固定可见。
- 卡牌数量增减控件不因数字位数变化而移动。
- 显示现有可计算的牌数、经验及构筑约束；规则错误指向相关卡牌或条件。
- 操作反馈使用局部数量变化和轻提示，不每次弹出模态框。
- 保存、导入失败保留用户输入；成功反馈以真实响应为依据。
- 离开未保存内容时遵循现有保存机制，若新增离开保护需单独实现。
- 不为方便布局而改变牌组校验、牌池或禁忌规则。

### 8.4 自定义卡牌与管理工具

对应 `CardBuilder.vue`、调试编辑器、`Admin.vue`、`Rooms.vue`。

- 表单、列表使用 Workbench 模式，装饰最低。
- 卡牌编辑采用字段区＋预览区，预览承载成品气质。
- 代码、对象编号和内部值只出现在确有必要的工具界面。
- 长表格拥有清楚列标题、空状态和错误定位。
- 管理操作按现有权限显示，危险操作说明作用对象和影响范围。

## 9. 游戏牌桌详细设计

### 9.1 桌面结构

对应 `Game.vue` 及现有 `Player.vue`、`Investigator.vue`、`Location.vue`、`HandCard.vue`、`SkillTest.vue` 等领域组件。

```text
┌────────────────────────────────────────────────────────┐
│ 剧本  回合／阶段         当前行动者       连接状态 菜单 │
├────────────┬─────────────────────────┬─────────────────┤
│ 调查员摘要 │                         │ 密谋／场景信息  │
│ 生命／理智 │      地点与卡牌桌面     │                 │
│ 资源／线索 │                         │ 当前提示与选择  │
│ 场上资产   │                         │ 日志／详情      │
├────────────┴─────────────────────────┴─────────────────┤
│ 当前玩家手牌与必要操作                                  │
└────────────────────────────────────────────────────────┘
```

1440px 宽屏可从左栏 240px、右栏 300px 起步，中间自适应。该数值必须用复杂真实场景校验，不可作为压缩卡牌至不可读的理由。手牌区域建议允许 150–220px 高度范围及用户收起，内容更多时局部浏览。

中央地图使用 `--surface-table` 中灰底；两侧信息栏和底部手牌承载区使用 `--surface-panel` 纸白底；顶部使用深石墨导航。各区有独立边界，普通正文均为深墨字。底部卡牌用接触阴影和卡槽辨识，不以大块暗底制造厚重感。

### 9.2 信息优先级

1. 待处理选择和当前行动窗口。
2. 与当前选择有关的卡牌、目标和费用。
3. 调查员状态与阶段。
4. 全局地点、场景和其他玩家信息。
5. 环境装饰。

每一时刻只建立一个主要操作焦点。强制处理窗口、可选反应和普通行动在提示中明确区别，最终是否可执行由现有规则数据决定。

### 9.3 地图与地点

- 原卡图保留完整比例，功能标识放在卡外或不遮挡信息的固定角位。
- 连接线使用清晰细线，方向和连接性质沿用规则数据。
- 调查员位置显示头像／标记与名称提示，多人同地点使用稳定堆叠或列表展开。
- 当前相关地点强调角部；不可操作地点维持可读，不全部压成黑色。
- 提供缩放、回到全图、定位当前调查员的设计入口；实施前确认现有地图控件能力。
- 地点增加后不得无提示改变用户当前视点；自动聚焦只用于明确事件并允许恢复。
- 不为了构图整齐更改规则相关的地点排列与连接。

### 9.4 卡牌状态

| 状态 | 视觉 | 交互 |
| --- | --- | --- |
| 默认 | 原图、按底面选用深／浅外轮廓、短阴影 | 查看详情 |
| 悬停 | 轻抬起、扩大预览 | 不自动执行行动 |
| 可操作 | 深青角标配浅色衬底及可用操作 | 点击进入实际选择 |
| 已选择 | 带深色衬线的黄铜边与勾选 | 支持规则允许的取消 |
| 耗尽 | 保留现有旋转语义并显示状态 | 详情仍可读 |
| 待分配伤害／恐惧 | 对应标记和待分配数 | 明确确认前后差异 |
| 密封／背面 | 正确背面与允许的信息 | 不通过预览或替代文本泄漏 |

选中轮廓、焦点环和职业边框可同时存在，使用不同位置及标记，不互相覆盖。

对黑色卡背、亮色卡面和多色插画分别校验。角标和勾选必须有稳定衬底，不让符号直接消失在相近卡面颜色中。

### 9.5 手牌

- 默认轻微重叠，保留卡名或足够的识别区域。
- 指针悬停时抬起预览，保持相邻卡的点击区稳定。
- 触屏点击打开详情，再提供明确行动；避免一次点击同时预览并出牌。
- 提供平铺／紧凑方向的设计，偏好只影响表现。
- 被遮住的卡可通过横向滚动或键盘访问。
- 手牌数量变化时保持当前选中项可见，避免整组剧烈位移。
- 其他玩家隐藏手牌完全遵循现有可见性规则。

### 9.6 调查员区域

- 头像、名称、生命、理智、资源、线索使用固定顺序。
- 职业色用细条或徽记，不给整块面板染高饱和色。
- 状态变化只短暂强调变化项，并保留最终数字。
- 多调查员切换区分“正在查看”和“当前行动者”，避免选中标签误导。
- 资产、威胁与其他区域保留现有分类，可在窄屏折叠为计数明确的分组。

### 9.7 行动提示

一个提示应回答：谁需要处理、为什么、有哪些目标、需要什么代价、如何确认。

推荐结构：阶段／来源 → 说明 → 可选目标 → 已选摘要 → 确认或取消。

- 选择数量显示“已选择 1／2”等可读文本。
- 禁用操作附带规则允许展示的原因。
- 高风险行为如结束回合，使用明确文字及当前状态提示，是否额外确认按误操作风险决定。
- 网络等待期间冻结同一提交入口，但保留查看详情与必要导航。
- 不将所有行动塞进无上下文图标菜单。

### 9.8 技能检定与混乱袋

集中面板依次展示：来源和难度 → 技能与投入 → 抽取标记 → 修正和效果 → 结果及后续。

- 数字算式清楚，基础值、投入、标记修正分开表达。
- 规则未确定结果前，只显示等待，不制作猜测性结果动画。
- 多标记、重抽、替换、祝福／诅咒等流程使用现有事件顺序，不假定每次检定只有一个标记。
- 标记展示保留既有符号与颜色语义，材质可增加细微边缘与落桌阴影。
- 成功使用低调亮边和文字；失败使用干血红印记及明确结果。
- 自动失败等符号效果按实际规则说明，不仅显示一个负数。
- 动画可加速或关闭；刷新、重连时不重复播放已处理的历史事件。
- 关闭详情不能跳过必须完成的规则选择。

### 9.9 日志、观战与回放

- 即时日志平时低强调，关键事件可展开读取来源和对象。
- 时间、玩家和事件内容分层，不能只靠颜色区分发言者。
- 观战明显标注只读；隐藏信息仍按权限控制。
- 回放增加时间轴、播放状态与定位控件，视觉上明确是历史状态。
- 回放拖动后不触发真实游戏提交或通知行为。
- 事件筛选、书签等属于可选增强，不能先于核心回放兼容性实施。

## 10. 多桌组织者与账户页面

### 10.1 组织者面板

对应 `OrganizerDashboard.vue`、`OrganizerBar.vue` 及事件组件。

- 定位为调查指挥室，保持工作台的信息效率。
- 顶部固定活动名称、倒计时和连接状态。
- 待组织者处理事项拥有最高优先级，显示规则来源和可用操作。
- 桌次列表展示玩家、调查员、席位和可进入状态。
- 分配类输入显示每桌上限、当前分配、总额及差额；不满足约束时清楚解释。
- 复制邀请链接给短反馈；链接本身可查看，避免仅依赖剪贴板成功假设。
- 倒计时结束、共享状态变化以服务端／现有业务逻辑为准，不由动画回调推进。
- 玩家与组织者操作区分，不能因新布局暴露越权动作。

### 10.2 登录、注册、密码与设置

- 账户页可使用氛围较强的侧图，表单区域保持纯净。
- 标签固定显示，错误紧邻字段；提交中的状态清楚。
- 保留自动填充、密码管理器和键盘提交体验。
- 设置按账户、语言、显示、交互等现有能力分组。
- 建议新增显示偏好：减少动态效果、牌桌密度、手牌表现；声音功能若未实现不显示无效开关。
- 系统错误使用准确描述，不用“古神拒绝了你”等文案替代故障原因。

| `UiDrawer` | 窄屏筛选和详情 | side、title、open |
| `UiStatus` | 图标与文字状态 | tone、label |
| `UiEmptyState` | 空内容与下一步 | title、description、action |
| `UiAsyncState` | 加载／错误／重试 | status、message、retry |

命名为建议，不要求一次替换所有现有组件。基础组件只处理视觉与通用交互，不调用游戏 API、不判断牌组合法性。

### 11.2 按钮状态矩阵

| 状态 | 主按钮 | 次按钮 | 危险按钮 |
| --- | --- | --- | --- |
| 默认 | 深孔雀绿、亮纸白字、细边 | 纸白底、深墨字、明确边框 | 浅纸底、深红图标和文字 |
| 悬停 | 轻提亮 | 轻背景与清楚边缘 | 危险底色轻增强 |
| 按下 | 轻微内压 | 同方向反馈 | 同方向反馈 |
| 焦点 | 外侧连续焦点环 | 同左 | 同左 |
| 加载 | 原标签保持，附加载标识 | 同左 | 同左 |
| 禁用 | 明确低强调、原因可获知 | 同左 | 同左 |

加载不改变按钮宽度。图标按钮必须有可访问名称。按钮类型显式声明，避免普通按钮意外提交表单。

### 11.3 弹窗与详情

- 工具弹窗使用亮纸白表面和深墨字；剧情弹窗使用档案纸。遮罩适度压低背景，不改变弹窗本身亮度。
- 标题、关闭入口、内容与操作区始终有稳定结构。
- 长内容内部滚动，底部确认可见且不挡正文。
- 打开时移动焦点，关闭后恢复至触发元素。
- Escape 和点击遮罩的关闭策略依交互性质设置，不丢弃未确认的重要输入。
- 卡牌大图预览与可交互详情区分：悬停预览不抢焦点，可交互详情使用合适的对话框语义。
- 不在普通提示气泡中放必须点击的主要动作。

### 11.4 文案规范

功能动词保持准确：创建战役、导入存档、继续游戏、确认投入、结束回合、重试。

气氛文案放在副标题或短提示，例如“卷宗尚未封存”。不得代替错误原因、操作结果或规则文本。

中文标点统一；数值单位清楚；长名称换行不挤掉按钮。所有新增可见文案进入翻译资源，保留动态名称，不对用户名称或内部标识执行碎片替换。

## 12. 动效、声音与环境模式

| 场景 | 形式 | 建议时长 |
| --- | --- | --- |
| 按钮 | 颜色与轻微压下 | 100–140ms |
| 卡牌悬停 | 抬起、柔和投影 | 140–180ms |
| 抽屉／详情 | 平移与淡入 | 180–240ms |
| 卡牌翻面 | 正反转换 | 240–320ms |
| 混乱标记 | 落下、稳定、展示 | 400–650ms |
| 剧情 | 局部渐显 | 可跳过 |

- 优先使用 opacity 和 transform，避免持续改变布局尺寸。
- 除用户触发外，默认无持续雾效、闪光、镜头抖动和呼吸光。
- 尊重系统减少动态效果设置，并可提供应用偏好。
- 动画结束不作为规则结算、提交请求或阶段推进的必要条件。
- 音效若实施，默认关闭；环境声和操作声分开控制。
- 声音只补充反馈，关键状态同时有文字和视觉。

可选场景配色：海岸冷青、书库暖褐、梦境灰紫。仅修改环境变量，游戏职业和交互状态颜色保持稳定。

## 13. 响应式与可访问性

### 13.1 断点策略

| 可用宽度 | 策略 |
| --- | --- |
| ≥1440px | 完整多栏牌桌，宽工作台 |
| 1100–1439px | 收紧边距，次要摘要可折叠 |
| 768–1099px | 侧栏抽屉化，保留当前提示 |
| <768px | 页面单列，游戏分区切换 |

以实际容器宽度和内容溢出决定最终断点，不能只按设备名称推断。低高度横屏还需减少顶部占用和手牌高度。

### 13.2 手机游戏

- 主区分为桌面、调查员、手牌，使用清楚的分区导航。
- 当前待处理事项有固定摘要，点击展开完整选择。
- 地图可缩放和平移，提供回到当前地点。
- 卡图打开全屏详情，并提供文字视图。
- 不允许普通页面整体横向溢出；地图和手牌的横向滚动是明确例外。
- 底部固定区考虑安全区域和软键盘，不遮住输入及确认。
- 分区切换保留浏览位置，但失效的选择必须依最新状态更新。

### 13.3 可访问性目标

- 普通正文对比度目标至少 4.5:1；大字和关键非文本控件按适用要求检查。
- 焦点在所有背景上可见，顺序与视觉阅读顺序一致。
- 交互目标优先达到 44×44px，可通过命中区域扩大而不放大图标。
- 标签页、弹窗、菜单具备完整键盘操作。
- 选中、危险、职业和在线状态具备非颜色线索。
- 游戏变化使用适度的状态播报，不逐条播报装饰或高频重复事件。
- 200% 文本放大下关键功能仍可用；卡牌提供可读文字替代。
- 隐藏卡牌的替代文本也必须遵守信息可见性。

## 14. 前端实现组织

### 14.1 分层职责

```text
设计 token：颜色／字体／间距／表面／动效
    ↓
基础 UI：按钮／字段／面板／弹窗／状态
    ↓
领域组件：卡牌／调查员／混乱袋／行动提示
    ↓
页面编排：路由／数据加载／区域布局
```

沿用 Vue 与现有状态管理。视觉组件接收状态并发出意图，领域层使用现有逻辑处理动作。不要建立第二套游戏状态真相。

### 14.2 Token 迁移

分为基础值、语义值、组件值三层。示意如下，仅为文档规格：

```css
:root {
  --surface-page: #c7c0b2;
  --surface-panel: #e8e1d2;
  --surface-raised: #f4efe4;
  --surface-table: #626e70;
  --surface-chrome: #303a3d;
  --text-primary: #252725;
  --text-secondary: #55594f;
  --text-on-chrome: #f4efe4;
  --border-panel: #817b70;
  --border-control: #69665f;
  --action-primary-bg: #28534d;
  --control-radius: 4px;
  --panel-radius: 6px;
  --motion-fast: 140ms;

  /* 迁移期间保留旧调用方，再逐页转成语义名称 */
  --background: var(--surface-page);
  --box-background: var(--surface-panel);
  --text: var(--text-primary);
}
```

- 不直接删除被大量组件使用的旧变量。
- 旧变量不能盲目一对一重映射：先区分其调用处属于浅色内容、深色导航还是中灰桌面，特别核对 `--background-dark`、`--background-light`、按钮文字、placeholder 与反白图标。
- 页面逐个迁移时同步修改表面和文字，防止出现纸白底上的旧灰白字。深色局部通过显式语义变量提供文字和焦点，不继承全局深墨字。
- `--select` 等变量先确认全部用途，再拆分为焦点、选中或可操作变量。
- 已有卡牌比例和尺寸变量单独管理，不混入普通面板 token。
- 迁移某页面时同时清理其硬编码颜色、阴影和重复装饰。

### 14.3 CSS 层级

现有入口已使用 reset、vendor、tokens、base、layout、components、utilities 层。Vue scoped 样式当前不在 layer 内，通常优先于 layered 规则。因此只改 tokens 或全局组件样式不保证页面全部生效。

实施要求：

1. 保留当前层级策略，先审计 scoped 覆盖。
2. 全局 base 只承担基础语义，不给所有 button 无差别加重装饰。
3. 基础组件拥有尺寸和状态，页面 scoped 主要安排布局。
4. 避免通过不断增加选择器权重或 `!important` 强制统一。
5. 自定义剧本样式有独立作用域，不能污染整个应用。

### 14.4 浮层与 z-index

现有 z-index 文件存在多个很大的数值，迁移时按实际覆盖关系整理，不能直接整体压缩而遗漏地图和第三方浮层。

期望相对顺序：背景 < 桌面物件 < 当前卡牌强调 < 固定工具区 < 下拉／抽屉 < 模态遮罩与内容 < 模态内部提示。

- 关闭弹窗后不得残留透明遮罩。
- 卡牌悬停预览不能覆盖正在操作的确认按钮。
- 模态内提示跟随所属模态，普通背景 tooltip 不跨越模态展示。
- 验证 transform、opacity 和定位形成的局部 stacking context。

### 14.5 状态与异步处理

- 展示状态区分 idle、loading、success、empty、error；空数据不等于加载失败。
- 提交状态区分可提交、提交中、失败和已完成，保留必要输入。
- WebSocket 更新中保留现有事件顺序和一致性处理，不以组件动画重排事件。
- 选中目标变为无效时及时说明，不悄悄提交其他目标。
- 主题和密度偏好可本地持久化；账号隔离和退出清理沿用项目规范。
- 不将服务端未提供的状态伪装成同步成功或规则通过。

## 15. 资产与性能

### 15.1 资产清单

| 资产 | 最小交付 | 规格方向 |
| --- | --- | --- |
| 主场景 | 横屏和竖屏可用裁切 | 局部夜景或灯下档案，限定在横幅／插画区，无嵌入 UI 文案 |
| 材质 | 亮纸、中灰桌垫、石墨构件三类 | 可平铺、低对比、无明显重复接缝，不压暗内容 |
| 装饰 | 角饰、分隔、索引、印章 | 优先 SVG，统一线宽 |
| 场景封面 | 按现有内容逐步覆盖 | 固定比例、统一标题安全区 |
| 空状态 | 无游戏、无结果、等待、错误 | 同一线稿体系 |
| 图标 | 通用功能图标清单 | 统一视觉尺寸与基线 |
| 字体 | 中文标题／正文及回退 | 确认字形覆盖与分发许可 |

建议将通用资产与场景资产分开存放，命名带用途和变体。具体目录在实施时结合现有资源组织确定，不复制多套相同纹理。

### 15.2 美术制作简报

场景插画：1920 年代调查室或雨夜街景，低饱和冷灰环境与温暖灯光，真实纸张和布料细节，远处存在难以辨认的异常；用于有限横幅或照片区，不铺满功能页面。主体工作区展示灯下明亮卷宗、中明度桌面与清楚的物件边界；不嵌入可读文字、按钮、巨大怪物主体或高亮符文，不增加全屏黑绿蒙层。

图像可以用作背景和封面，功能边框、图标、排版尽量由矢量与代码控制，以适配中文、缩放和交互状态。

### 15.3 性能目标

- 首屏先具备可读内容和可操作骨架，氛围大图渐进加载。
- 装饰图片使用现代压缩格式并保留适当兼容方案，按显示尺寸提供资源。
- 首屏新增装饰资源以总量不超过约 500KB 为初始预算；超出时需证明视觉收益并测量影响。
- 不预加载整个卡牌库图片，已有卡图缓存和资源策略先复用。
- 字体控制字重数量，按可靠的语言或字形范围拆分，避免缺字。
- 滚动和牌桌交互以流畅为目标，出现掉帧时先减少模糊、阴影范围及实时纹理。
- 低性能模式可关闭纹理和动画，但保持信息及操作完整。
