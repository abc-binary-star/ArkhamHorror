# 游玩体验扩展方案：调查、协作与战役档案

日期：2026-09-30。状态：方案，未实施。依据当前工作区代码与已有设计文档；未启动游戏、构建或浏览器验收。

## 设计目标

让玩家在牌桌上多一些值得操作、记录和回味的东西：能整理自己的调查思路、在地图上规划下一步、向队友表达意图，并把一场战役留下来。

界面继续采用墨绿桌面、象牙纸、旧铜索引和低饱和印章。新增功能都有具体用途，地图与卡牌仍占主要空间。规则操作保持现有入口和服务端裁定。

## 现有基础与本轮增量

当前工作区已存在并接入数值反馈、反馈历史、附着特效、牌桌主题、检定结果拆解、章节交接等代码；这些功能的完整运行表现未在本次确认。另有游戏日志、逐步回放、调查员统计、战役记录与成就入口。

本方案在这些基础上增加交互工具与战役体验，和 `gameplay-visual-experience-plan.md` 的行动动画方案分开推进。

| 新增方向 | 现有可复用部分 | 需要新增的能力 |
|---|---|---|
| 调查板 | 卡牌详情、地图定位、工具抽屉 | 引用已知实体的笔记、置顶与手动待办 |
| 地图计划 | 地点连接、地图缩放与拖动 | 独立的路线草稿和地点注记 |
| 手牌工作台 | 原有手牌与打牌入口 | 本地排序、用途分组与收藏标记 |
| 队友协作 | 玩家页签、游戏连接 | 标点和意图的独立联机协议 |
| 专注布局 | 现有牌桌布局、检定最小化 | 手动切换阅读、规划和常规布局 |
| 战局续接 | 当前游戏状态、日志、反馈历史 | 离开时的个人书签与回来后的差异摘要 |
| 战役档案 | 战役记录、章节交接、成就 | 玩家注释、已公开故事索引和个人收藏 |
| 精彩回顾 | 回放、日志、统计 | 可寻址的事件书签与结局后的纪念页 |

## 1. 调查板：把线索和想法留在桌上

**体验。** 玩家打开“调查板”，把已公开的地点、敌人、故事卡钉进去，写下“这个门还没处理”“下一轮回来拿线索”。它既能做个人记事，也能承载小队目标。

**UI。** 桌面端复用侧边抽屉位置，纸面条目配小卡图、短注释和定位按钮；窄屏采用单个底部面板。最多三项置顶目标显示在抽屉收起后的摘要中，其余展开查看。首版使用列表，后续再考虑自由摆放和连线。

**首版范围。** 新建笔记、引用实体、置顶、手动勾选待办、定位原卡。支持纯文字，实体离场后保留“已离场”引用。

**边界。** 手动目标明确标注“玩家计划”，和官方场景目标分开。首版不从卡牌正文自动提取胜利条件，也不自动判断玩家目标完成。引用只能来自当前用户有权看到的信息；私密手牌引用只存在个人笔记中。

**实现。** 前端即可完成同一设备的个人版；存储按账号、游戏与剧本实例隔离。战役笔记另设战役作用域。跨设备和小队共享需要后端持久化及访问控制。

**验收。** 刷新保留笔记；切换账号和游戏不串数据；同名卡按实体区分；地图变化后定位正确；回放中历史实体的可见性按所选步骤判断。

## 2. 地图计划：在地点之间画下一步

**体验。** 点击“规划”，依次选择地点，留下“大厅 → 走廊 → 书房”的路线草稿；每个节点能附一句行动想法，例如“先清敌人，再调查”。一控多角色时可以为不同角色保留各自路线。

**UI。** 使用细虚线与编号纸签。规划模式有清楚的状态条，以及撤回节点、清空、退出按钮。退出后路线可隐藏或淡显；常规游戏点击恢复原行为。

**首版范围。** 玩家手动选择可见地点、添加节点和备注；只按已公开连接校验地图连通性。路径之外的临时传送或特殊移动，通过文字注记表达。

**边界。** 地图相连不代表调查员可以合法移动。路线只表达计划，不能按普通连线推算真实行动成本；特殊移动、单向限制和附着效果仍以实际选项为准。首版不提供自动执行路线。

**实现。** 前端保存地点 ID 和顺序，线条在地图本地坐标中绘制，复用现有缩放与布局。地点移除或连接变化时标记路线失效，保留注释供修改。小队共享放到协作阶段。

**验收。** 缩放、拖动和固定 16:10 模式下路线贴合地点；规划点击不会触发移动；退出不残留输入拦截；未知地点不出现隐藏名称或连接。

## 3. 手牌工作台：整理这一轮的打法

**体验。** 在手牌区按费用、类型或技能图标排序，也可以自己划分“本轮准备”“留作投入”“以后使用”。多牌时更容易形成行动思路。

**UI。** 手牌上方放一条收起式整理栏；分组使用细分隔和小纸签。收藏卡加角标，不另复制一张卡。默认保留当前排列，玩家主动选择排序后生效。

**首版范围。** 本地排序、手动分组、单卡收藏、恢复原顺序。触屏提供菜单操作，拖动属于可选捷径。

**边界。** 按印刷费用排序时明确显示“印刷费用”，不能包装成当前可支付费用。投入分组只是记事，不能承诺该牌在当前窗口可以投入。展示顺序变更后仍按原始 choice index 提交，不能把排序下标当选项索引。

**实现。** 在实际手牌渲染入口增加展示适配层；分组以卡牌实例 ID 保存，不按牌名合并。卡牌离开手牌时清理该实例的分组。仅处理本人或当前控制角色可见的手牌。

**验收。** 两张同名牌可分别分组；排序后打出的是正确实例；多选与检索不受影响；控制角色切换后分组不串；整理过程不泄露队友手牌。

## 4. 队友标点与意图：让协作落在地图上

**体验。** 对公开地点或敌人发送“去这里”“我来处理”“需要协助”“注意危险”。角色页签旁可以挂一条短意图，例如“这轮负责清敌人”。单人多角色也能用持久的意图便签规划分工。

**UI。** 卡牌菜单提供标点入口；地点边缘短暂显示带发送者头像的圆环和文字，约 3 秒后淡去。意图便签保持静止，支持清除。手机通过显式菜单进入，不依赖右键或长按。

**首版范围。** 四种预设标点、单条角色意图、清除、接收提示开关。先使用结构化文案，减少输入成本。

**边界。** 标点不发起行动，不宣告实际回合顺序，不提前表示投入完成。观战者默认不发送。私密卡牌不可成为共享目标；目标在接收端不可见时不携带牌名等隐藏信息。

**实现。** 新增协作消息类型，独立于规则回答和游戏撤销记录。服务端校验成员身份、目标可见性、发送频率；短标点有事件 ID 和过期时间，重连不补播。角色意图按房间持久化，带版本处理并发更新。

**验收。** 两个玩家即时收到同一个公开目标的标点；过期和重连不重播；退出房间后不能继续发送；撤销游戏不会撤销聊天式标点；断线时明确显示发送失败。

## 5. 专注布局：同一张牌桌，按当前需要展开

**体验。** 玩家手动切换“常规 / 地图 / 阅读”。地图模式扩大地图并压缩非必要区域；阅读模式给故事和卡牌正文留出更舒适的宽度；常规模式恢复现有完整牌桌。

**UI。** 在现有查看菜单中加入布局切换，避免再造一条常驻工具栏。布局变化时保留地图中心、选中角色和阅读位置；窄屏对应为不同面板的优先展开。

**首版范围。** 三种手动布局与恢复按钮。后续再考虑玩家明确开启的上下文建议。

**边界。** 三种布局都保留当前操作者、待答问题、连接状态、关键资源和返回入口。需要处理的问题出现时显示稳定的操作入口；不会因为布局收起而丢失强制效果、伤害分配或检定操作。首版不自动切布局。

**实现。** 在现有布局上调整区域展开状态和宽度，复用同一组组件和状态，减少组件卸载造成的阅读、弹窗和地图状态丢失。

**验收。** 常规、地图、阅读布局间反复切换仍能处理相同决策；多人页签和固定牌桌正常；短屏、手机、长中文不挡操作。

## 6. 战局续接卡：隔几天回来，马上知道该做什么

**体验。** 玩家点“记住当前进度”，保存一张个人书签。下次回来看到一张可收起的小卡：“当前由谁操作、你在哪、还有哪些未处理威胁、之前留下了哪些计划”。若离开期间有人推进，则列出能确定的公开状态变化。

**UI。** 卡片出现在侧边，可点击定位调查员、敌人和笔记；不增加进入游戏的确认步骤。只在有效书签存在时提示一次，随时可从工具菜单重新打开。

**首版范围。** 个人书签、当前局面摘要、与书签的确定性差异、调查板未完成目标。首次进入只展示当前摘要，不虚构“上次发生了什么”。

**边界。** 现有反馈历史是运行期信息，不能直接当跨会话档案。状态差异只说明“现在相比之前怎样”，不能补写未记录的行动因果。中途进出场的敌人等历史变化，仅有两个快照时不作叙述；需要准确经过时接入持久事件。

**实现。** 首版保存少量可见字段与版本标识。撤销到早于书签、换剧本或读取其他存档时将书签标为不适用，保留玩家文字笔记；跨设备需要服务端个人书签。

**验收。** 正常返回、队友推进、撤销、重连和切章节都不会误报；本人私密快照不进入共享接口；原决策流程可以直接操作。

## 7. 战役档案：让经历变成一本可翻的记录

**体验。** 每个已游玩的章节成为一页档案，收纳已公开故事、确认的结果、调查员创伤与经验、玩家写下的一句话。玩家可收藏一个地点或故事片段，作为这次战役的记忆。

**UI。** 从现有战役日志进入“章节档案”页签。章节索引像纸质隔页，正文以稳定阅读为主；收藏用小型印记。首次进入只展开有内容的当前章节。

**首版范围。** 当前章节公开资料与个人注释、明确的结算记录、收藏索引。已公开故事允许检索，未公开条目不展示标题、图片或占位数量。

**边界。** 现有战役日志不必然保存每段故事的原文与公开时间。完整历史故事需要新增公开内容索引，不能用本地卡牌数据库反推出玩家还没见到的章节。多次重玩按战役和剧本实例分册；个人收藏不会改变官方成就。

**实现。** 先整合现有最终记录和玩家注释，再增加带可见性信息的故事归档事件。对过去存档没有的数据显示缺失，不伪造完整档案。

**验收。** 未推进章节无剧透；跨章节记录归属正确；创伤、经验和结局来自最终确认状态；收藏移除与战役重玩互不混淆。

## 8. 精彩回顾与纪念卡：打完之后还能回味

**体验。** 玩家把一次险过检定、关键救援或重要推进标为“精彩时刻”，战局结束后在回顾页快速重看。确认结局后生成一张纪念卡：剧本、阵容、最终结果、现有统计和一句玩家寄语。

**UI。** 回放页增加可点击的时间线书签。纪念卡采用纸面与小幅场景图，可导出图片；展示重团队经历，统计沿用线索、伤害等现有数据。

**首版范围。** 手动事件书签、跳转有效回放步骤、结束后的纪念卡。自动精彩识别作为后续扩展；没有明确事件与回放定位关系时只保存文字记录。

**边界。** 服务端回放步骤和实时日志之间的对应关系要先核对，不能把日志行号当回放步数。保留历史受撤销模式影响：步骤被裁剪后书签显示“仅保留记录”。纪念卡在最终结算结束后可用，默认不导出私密手牌和个人笔记。

**实现。** 新增事件/书签到可用回放步骤的稳定映射；初版导出只用确认数据和现有素材。旧存档不补造不存在的时刻。

**验收。** 书签跳转正确；撤销和历史裁剪后无错跳；导出与最终结果一致；长名字、多调查员、失败或特殊结局均能排版。

## 共用 UI 组织

- 常态牌桌只增加一个“调查板”入口；地图计划放进地图控件，手牌整理留在手牌区，其余使用现有查看、工具、战役日志和回放入口。
- 新增侧边工具遵循同一套抽屉管理：打开调查板时收起其他非必要工具，保留玩家正在处理的规则弹窗。手机一次只展开一个工具面板。
- 纸签、铜色索引、虚线路线负责功能区分，文本保持清晰。卡牌中心不叠笔记正文，规划线条放在牌图下方，数字与操作高亮处于上层。
- 玩家记录、官方规则、当前决策分别有明确标题与图标，配合文字区分，不只靠颜色。
- 地图规划和标点提供显式菜单，所有功能支持键盘或触屏。新增快捷键先核对现有 Q/W/E/R 等绑定；Esc 只退出当前工具，不默认代替取消规则选择。
- 可选动效短暂且不锁交互。减少动态模式使用静态环和文字；动画不改变规则队列。

## 实施优先级

工作量是相对估计，不是工期承诺；依据是本次代码阅读，尚未完成详细协议与数据迁移设计。

| 阶段 | 内容 | 工作量 | 阶段交付 |
|---|---|---|---|
| 第一批 A | 地图计划 + 手牌工作台 | 中 | 每回合能用上的两个工具，首版个人使用 |
| 第一批 B | 调查板个人版 + 专注布局 | 中 | 整理调查思路并改善阅读、规划空间 |
| 第二批 | 标点与意图共享 + 调查板共享 | 大 | 可在真实联机中沟通目标，后端负责权限和同步 |
| 第三批 A | 战局续接卡 + 章节档案基础版 | 中至大 | 回来时能续接，结束后有可查询的记录 |
| 第三批 B | 精彩回顾 + 纪念卡 | 大；仅纪念卡为中 | 建立回放定位与历史保留后形成完整回顾体验 |

建议先完整完成第一批 A，再做第一批 B。地图画路线和手牌分组会让玩家立即感到玩法交互变丰富；调查板与专注布局随后把这些工具组织起来。多人联机功能在同步协议具备后单独交付。

## 工程落点与数据边界

- `Game.vue`：工具入口、抽屉管理、个人续接入口。`Scenario.vue` / `ScenarioMapControls.vue`：地图计划、标点和布局区域。手牌需追踪实际渲染入口，不只修改调查员展示组件。
- `useMapViewport.ts`：沿用坐标和视口状态；新增叠层不改变地点拖动保存。`ReplayGame.vue`：时间线与书签导航。`CampaignLog.vue` / `ChapterHandoff.vue`：档案入口和已确认记录。
- 个人展示设置、玩家注释、规则状态分别保存。首批工具使用独立前端存储，不写入规则快照；共享协作使用独立后端数据与消息类型，不塞入 choice 回答。
- 现有 `useGameSocket.ts` 提供连接基础，但不等于已支持协作消息。新增协议应兼容旧消息处理，并明确持久意图与短期标点的恢复策略。
- 数据以实际实例 ID 为主，记录游戏、剧本实例、作者和版本。所有共享内容在服务端验证访问范围；前端隐藏不能代替隐私隔离。

## 交付验证

代码实施时重点检查排序后选项映射、地图坐标、个人数据作用域、联机权限、重连去重、撤销后引用和回放步骤有效性。按每批具体变更执行必要的代码检查。

运行态和视觉验收在明确要求后进行，覆盖单人、多角色、真实联机、观战、自适应与固定 16:10，以及桌面、低高度窗口和手机。最终交付分别说明代码实现、静态检查和实际游玩验收状态。

本次仅新增本方案文档，未修改游戏代码，也未改动工作区已有方案。
