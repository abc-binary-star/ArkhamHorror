# 「诡镇奇谈」前端 UI 设计方案

版本：1.1 · 2026-09-09  
适用项目：`arkham-horror` 前端  
设计目标：把现有界面从“统一主题的功能 demo”提升为有完整美术指导、叙事气场和物件质感的商业级克苏鲁桌游产品界面。

## 0. 先说结论

现有代码已经具备暖灰页面、纸面面板、中灰牌桌和完整路由，但视觉重心仍在“组件是否统一”。下一版要先建立作品的第一印象，再让组件服从作品：

- 首页是**一张有叙事的海港档案封面**，不是标题加列表。
- 组牌与卡牌库是**调查员的精密工作台**，不是普通后台筛选器。
- 游戏页是**一张可读、可操作的实体牌桌**，不是把卡牌贴在网页背景上。
- 氛围来自构图、材质、光线、排版和信息节奏；触手、眼睛、血迹只在剧情节点出现。

美术参考的共同点是高完成度的实体物件、清楚的视觉焦点、深青与旧纸的对比、以及用少量黄铜和暖光制造收藏品感。《蚀教追猎》众筹页的主视觉采用了深青场景、旧纸标题牌、产品物件和分栏信息的组合；本方案吸收这种层次关系，所有插画、徽记和文案保持本项目原创。[参考：摩点《蚀教追猎》项目页](https://zhongchou.modian.com/item/156979.html)；克苏鲁题材的核心仍然是调查员面对不可理解的古老力量，因此恐惧应以尺度、雾和建筑暗示呈现，而不是持续展示怪物。[参考：CMON 的美术说明](https://www.cmon.com/cthulhu-death-may-die-art-and-aesthetics/)

## 1. 品牌概念：诡镇奇谈

### 1.1 一句话

玩家打开应用，像从一只锁着的海关档案柜中取出案件：潮湿的港口、编号的卷宗、调查员证件、尚未解释的符号，以及一张正在等待摆放卡牌的牌桌。

### 1.2 三种视觉角色

| 角色 | 视觉语言 | 负责页面 |
| --- | --- | --- |
| 档案馆 | 象牙纸、打字编号、照片角钉、窄黄铜线 | 首页、战役日志、成就、账户 |
| 调查工作台 | 浅木／灰布、分栏、卡槽、可拖拽的纸牌 | 卡牌库、牌组列表、牌组编辑、新战役 |
| 诡镇牌桌 | 中明度石板灰桌垫、局部冷雾、纸面 HUD | 游戏、观战、回放 |

三者共用字体、按钮、焦点环和状态语义，只替换背景材质和装饰密度。

### 1.3 设计原则

1. 第一眼先看到“这是一件作品”，第二眼才看到功能。
2. 操作区域必须安静、明亮、稳定；叙事装饰停留在边缘。
3. 质感由真实的材质比例建立：细边框、接触阴影、纸张纤维、压印和磨损，而不是厚重阴影和滤镜。
4. 中文排版要有书籍感，英文和编号承担档案感，不能让装饰字体承载规则。
5. 重要信息有明确层级：当前战役 > 当前行动 > 可执行按钮 > 辅助说明。
6. 装饰不改变业务，不遮挡卡牌，不降低文字对比度，不制造持续闪烁。

## 2. 现有前端的改造边界

不更换 Vue 3、TypeScript、Vite、Pinia、Vue Router、vue-i18n，也不改变游戏规则、回放、观战、权限、卡牌数据和已有翻译。

| 现有位置 | 本方案的落点 |
| --- | --- |
| `frontend/src/styles/tokens.css` | 新增材质、色板、层级、动效和版式 token；移除旧 Neo-brutalist 语义残留 |
| `frontend/src/styles/base.css` / `components.css` | 统一纸面、按钮、输入框、标签、通知、对话框和状态 |
| `frontend/src/styles/layout.css` | 三种 Shell、主容器、分栏、牌桌区域和响应式断点 |
| `frontend/src/styles/fonts.css` | 接入完整中文宋体／黑体；专用图标字体只用于图标 |
| `frontend/src/views/Home.vue` | 重构为封面式当前调查 + 进行中战役档案 |
| `frontend/src/arkham/views/Decks.vue` / `Deck.vue` | 工作台分栏、牌组统计、卡牌卡槽与拖拽反馈 |
| `frontend/src/arkham/views/Cards.vue` | 可折叠卡池索引、筛选条和卡牌浏览画廊 |
| `frontend/src/arkham/views/Game.vue` | 牌桌 Shell、侧栏纸面 HUD、行动区和局部叙事覆盖层 |

所有现有业务组件继续提供数据和事件。先抽取视觉壳层，再移动 scoped 样式；不要在视觉重构中顺手修改行动合法性或 API。

## 3. 美术指导

### 3.1 构图

- 使用左上暖光、右侧重细节、中央留操作空间的构图。
- 首页主视觉保留约 35% 的低细节雾面安全区，用于叠放标题和“继续调查”。
- 场景元素遵循远景、中景、前景三层：远景是雾与海，中景是建筑和灯塔，前景是卷宗、栏杆、调查员或卡槽。
- 不把完整怪物放在每个页面中心；未知力量应被建筑、尺度、倒影、缺口和不完整符号暗示。

### 3.2 材质

| 材质 | 使用位置 | 处理方式 |
| --- | --- | --- |
| 象牙档案纸 | 面板、剧情、日志、弹窗 | 极轻纸纤维；四边 1px 结构线；局部压印编号 |
| 深海石板 | 导航、牌桌边框 | 低对比布纹；不做纯黑；反白文字 |
| 氧化黄铜 | 分隔线、角饰、选中边框 | 暗金底 + 单侧高光；不大面积填充 |
| 湿木与皮革 | 首页封面、牌组封套 | 只做大图或边缘材质，不放在长文本下面 |
| 玻璃／雾 | 剧情覆盖层 | 只在短时剧情状态使用，正文仍放实色纸面 |

### 3.3 装饰规则

- 标题最多一组角饰、一条分隔线和一个编号章，不重复堆花边。
- 角饰使用不闭合的天文弧线、经纬刻度和档案孔位，避免通用五芒星。
- 旧化只发生在边缘，正文背景保持干净。
- 印章代表“已归档、危险、成功、失败”等文档状态，不能代替按钮状态。
- 禁止全局霓虹紫绿渐变、厚黑描边、所有卡片都浮起、连续烟雾和随机闪烁。

## 4. 色彩与字体系统

### 4.1 色板

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--fog-page` | `#BDB8AD` | 页面底色，暖灰雾面 |
| `--paper` | `#E9E1D2` | 普通档案纸 |
| `--paper-bright` | `#F7F1E6` | 输入框、弹窗、重要信息 |
| `--slate-table` | `#657174` | 牌桌中央，保证卡面可读 |
| `--deep-sea` | `#26373A` | 导航、牌桌边缘、页脚 |
| `--ink` | `#242827` | 主要正文 |
| `--ink-soft` | `#5D625C` | 辅助信息 |
| `--brass` | `#A5824B` | 细线、角饰、选中态 |
| `--brass-light` | `#D0B47B` | 关键徽记和高光 |
| `--harbour-teal` | `#28615D` | 主操作、链接、进度 |
| `--danger-oxide` | `#9B4D45` | 伤害、错误、危险 |
| `--occult-violet` | `#75668A` | 神秘事件，面积不超过 2% |
| `--focus-cyan` | `#1E6973` | 键盘焦点环，双线或外环 |

规则：页面底色、纸面、亮纸和牌桌必须在灰度下可区分；深海色只承担导航和边缘；黄铜不用于小字号正文；职业色、生命、理智和混沌袋颜色继续遵守游戏语义。

### 4.2 字体

优先采用思源宋体（Source Han Serif）作为中文标题和剧情字体，思源黑体（Source Han Sans）作为工具与正文。两套字体均提供 CJK 字形；正式接入前做授权、文件体积和中文字形覆盖检查。[思源宋体项目说明](https://github.com/adobe-fonts/source-han-serif)；[思源黑体项目说明](https://github.com/adobe-fonts/source-han-sans)。

| 用途 | 字体 | 桌面 | 手机 |
| --- | --- | --- | --- |
| 品牌／页面标题 | 思源宋体 Semibold | 34/44 | 27/36 |
| 区块标题 | 思源宋体 Semibold | 22/31 | 19/28 |
| 剧情与日志 | 思源宋体 Regular | 18/31 | 17/29 |
| 正文 | 思源黑体 Regular | 15/25 | 15/25 |
| 按钮／工具栏 | 思源黑体 Medium | 14/20 | 14/20 |
| 编号／数值 | 思源黑体 + 等宽数字 | 12–14/18 | 12–13/18 |
| 英文副标 | Arno 或现有 `Arno` | 11–13px，大写，0.12em 字距 | 同左 |

屏幕中最多出现三类文字风格。装饰手写字体只能出现在短批注或印章，图标字体不得作为中文回退字体。

### 4.3 几何与层级

- 间距：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px`。
- 页面内容宽度：桌面 1280px，超宽屏 1440px；手机边距 16px。
- 面板内边距：常规 24px，紧凑表格 16px，牌桌 HUD 12–16px。
- 控件：40px；触控目标不小于 44px；圆角 3–6px。
- 结构边框 1px；选中态增加 2px 黄铜内线或外环，不用 6px 粗描边。
- 卡牌使用真实比例和统一卡槽，不因页面缩放而拉伸变形。
- 阴影只表示物件与浮层：卡牌 `0 3px 8px rgb(24 29 28 / 20%)`，弹窗 `0 18px 46px rgb(24 29 28 / 28%)`。

## 5. 三类页面 Shell

### 5.1 `ArchiveShell`

首页、日志、成就、账户使用。背景是暖灰雾面，顶部导航深海色，内容放在象牙纸上；仅首页首屏使用大图。

### 5.2 `WorkbenchShell`

卡牌库、牌组列表、牌组编辑、新战役使用。左侧是索引／章节，中央是结果或编辑区，右侧可选统计和预览。工具栏固定在工作区顶部，滚动只发生在列表内部。

### 5.3 `TabletopShell`

游戏、观战、回放使用。中央中灰牌桌承载地点、调查员、敌人和卡牌；左右侧栏是纸面信息；底部为手牌与行动区。侧栏打开时不得把地图压缩到不可玩，应改为覆盖或折叠。

## 6. 核心页面方案

### 6.1 首页：当前调查封面

首屏结构：

```text
┌──────────────────────────────────────────────────────────────┐
│  诡镇奇谈  调查  牌组  卡牌  战役日志             账户  ⚙   │  深海导航
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  案件档案 04-17             [主视觉：诡镇、灯塔、远古轮廓]   │
│  ARKHAM HORROR             [安全区：标题、继续调查]          │
│  潮声从档案室下面传来。                                      │
│  [继续调查]  [导入存档]                                      │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│ 当前调查  ·  进行中                                          │
│ [战役封面]  战役名／当前剧本／调查员／理智与生命／继续 →      │
├──────────────────────────────────────────────────────────────┤
│ 其他战役档案       最近事件／通知              已归档（折叠） │
└──────────────────────────────────────────────────────────────┘
```

- 主视觉高度为首屏 300–440px（桌面），移动端 240px；标题放在雾面安全区，不压在建筑细节上。
- “继续调查”是唯一高权重实心按钮；“导入存档”使用纸面描边按钮。
- 战役条目以档案卡呈现：固定封面比例、左侧状态章、中央信息、右侧动作；删除操作放到更多菜单。
- 空状态不是一块空白盒子，而是一张“待建立案件”纸张，给出创建战役和浏览牌组两个动作。

### 6.2 卡牌库：索引柜 + 展示桌

- 顶部显示当前卡池、搜索、筛选、列表／画廊切换；筛选结果即时反馈数量。
- 左侧索引以“循环 → 卡组 → 章节”树呈现，每层有细黄铜刻度和数量，不使用一串彩色胶囊。
- 画廊卡牌有 8px 间距和统一卡槽；hover 只抬升 2px 并出现纸张边缘光，不做发光。
- 卡牌详情从右侧滑入纸面抽屉，展示卡图、规则文本、配套卡和收藏状态；移动端改为全屏纸面。
- 没有结果时显示“档案柜中没有匹配记录”，保留清除筛选动作。

### 6.3 牌组列表与牌组编辑：调查工作台

- 列表卡显示调查员肖像、职业色窄条、牌组名、卡数、资源曲线和最近修改时间。
- 牌组编辑采用三栏：左侧牌组结构，中间卡牌列表／拖拽区，右侧调查员与合法性摘要。
- 右侧统计使用纸张上的细线图表；合法性错误用氧化红 + 文本原因，不能仅用红色边框。
- 拖拽时显示“插入位置”黄铜线；放下后卡槽有一次短促的纸张落桌反馈。
- 卡牌替换、删除、恢复都必须有明确的撤销入口；不把危险操作藏在装饰菜单里。

### 6.4 新战役：两页式档案登记

第一步选择战役／剧本：左侧封面与章节缩略图，右侧名称、人数和时长。第二步设置选项：将高频设置分为“游戏规则”“叙事选项”“多人选项”，其余折叠在高级设置。

底部固定“上一步／建立调查”操作条，顶部显示 `01 选择剧本 · 02 设置调查` 进度。完成后先出现一张“案件已立档”纸面确认，再进入游戏。

### 6.5 游戏牌桌：实体比例和可读性优先

```text
┌──────────────┬────────────────────────────────┬──────────────┐
│ 调查日志纸面 │        中灰石板牌桌             │ 当前行动纸面 │
│ 可折叠       │ 地点／敌人／调查员／卡槽        │ 轮次／提示   │
│              │                                  │              │
├──────────────┴────────────────────────────────┴──────────────┤
│ 手牌卡槽             当前行动：调查／移动／交战       结束回合 │
└───────────────────────────────────────────────────────────────┘
```

- 地图中央保持中明度、低纹理；地点卡使用明显浅色卡槽和编号。
- 当前行动者使用黄铜框 + “当前行动”文字；等待玩家使用静态纸签，不让整桌闪烁。
- 技能检定、选择、混沌袋、故事问题都是纸面浮层，宽度 420–560px；长文本不直接放在牌桌反白。
- 关键事件可以短暂改变边缘冷暖光，结束后恢复；不覆盖卡牌数字和按钮。
- 日志、历史、快捷键和调试菜单共享一个纸面抽屉系统；关闭抽屉不重置地图滚动位置。

## 7. 交互与状态

| 状态 | 视觉 | 必须同时提供 |
| --- | --- | --- |
| 可操作 | 深海按钮或青色角签 | 动作名称、键盘可达 |
| hover | 2px 抬升、窄高光 | 不改变布局 |
| focus | 2px `--focus-cyan` 外环 | 键盘焦点顺序清楚 |
| selected | 黄铜边框 + 勾选或“已选择” | 不只依赖颜色 |
| disabled | 降低对比度但保留边界 | 原因提示 |
| loading | 静态“正在读取档案” + 局部占位 | 不用全屏旋转 |
| error | 氧化红标题 + 原因 + 重试 | 错误可恢复 |
| waiting | 纸签“等待某某完成……” | 显示玩家和等待事项 |
| dangerous | 深红小面积底色 | 说明后果和取消入口 |

动效只做三类：页面进入的纸张滑入（180–240ms）、卡牌落桌（120–180ms）、剧情揭示的边缘光（不超过 900ms）。遵守 `prefers-reduced-motion`，关闭动效后状态仍然完整。

## 8. 响应式规则

| 视口 | 规则 |
| --- | --- |
| ≥1280px | 三栏工作台；牌桌双侧栏；首页主视觉 + 档案列表 |
| 900–1279px | 工作台右栏变抽屉；首页主视觉缩短；游戏侧栏可折叠 |
| 600–899px | 导航收为品牌 + 菜单；卡牌库索引变横向抽屉；牌桌只保留一个信息抽屉 |
| <600px | 单栏；标题和按钮可换行；手牌水平滚动；所有浮层全屏纸面 |

移动端不缩小关键操作到难以点击的尺寸；卡牌可用水平滚动和“查看详情”完成操作。低高度窗口优先保留行动条和手牌，日志自动折叠。

## 10. 工程实施顺序

### P0：作品气场

1. 新增三类 Shell 和页面背景层。
2. 接入 `01-诡镇奇谈主视觉.png`，完成首页封面、标题安全区和当前调查档案卡。

完成标准：打开首页 3 秒内能识别品牌、当前战役和继续入口；即使隐藏文案，也能看出档案／牌桌世界。

### P1：组件质感

1. 纸面、桌垫、黄铜线、卡槽、按钮、输入框和抽屉。
2. 完成 loading、empty、error、focus、selected、waiting 状态。
3. 接入中文字体并做长标题、数字、英文混排检查。

完成标准：同一按钮、卡槽、通知和浮层在首页、组牌、牌桌中外观和状态一致。

### P2：核心页面

1. 首页 → 新战役 → 牌组编辑 → 卡牌库。
2. 游戏牌桌和行动纸面 HUD。
3. 观战／回放／日志复用同一抽屉和时间线。

完成标准：核心流程从建立战役到进行一次行动，视觉语言连续，未改变任何游戏数据语义。

### P3：收口与验收

1. 生成牌桌材质和纸纹理，优化资源体积。
2. 桌面、平板、手机真实视口截图回归。
3. 灰度检查、键盘检查、减少动态效果检查、字体覆盖检查。
