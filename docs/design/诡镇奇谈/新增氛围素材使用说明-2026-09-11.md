# 诡镇奇谈 · 新增氛围素材使用说明

版本：1.0 · 2026-09-11  
范围：`frontend/public/assets/veiled-harbour/` 新增的 42–49 号 PNG 素材

状态：本批素材已接入项目页面；本文同时作为后续素材批次的落位清单。

## 1. 本轮结论

项目现有视觉已经建立了“深海石板 + 象牙档案纸 + 氧化黄铜”的产品语言，缺口主要不在按钮纹理，而在页面之间的叙事氛围：

1. 首页需要一张具有明确文案安全区、能替换使用的海港案件主视觉。
2. 战役／章节选择需要一张能承载标题的竖版封面，而不是继续裁切横版 Hero。
3. 工作台、房间和牌桌外围需要一个更完整的“午夜档案馆”环境，中央区域仍要留给 UI。
4. About、空状态和说明卡需要一个可以独立摆放的古旧静物锚点，增加典雅感，但不能把装饰变成控件背景。

本轮素材全部不包含文字、Logo、规则文本和具体战役名称。文案、数字、本地化和无障碍信息继续由 HTML／Vue／i18n 负责。

## 3. 接入位置与方式

### 3.1 首页：`42-旧港雾潮主视觉-v1.png`

对应代码位置：`frontend/src/views/Home.vue` 的 `.home-hero`。当前这里使用 `01-诡镇奇谈主视觉.avif`，本轮素材可作为新的 Hero 版本候选，不建议直接删除旧素材。

桌面端建议：

```css
.home-hero {
  background:
    linear-gradient(90deg, rgb(20 34 35 / 0.78) 0%, rgb(20 34 35 / 0.42) 42%, transparent 78%),
    url('/assets/veiled-harbour/42-旧港雾潮主视觉-v1.png') center / cover no-repeat;
}
```

使用规则：

- 标题、说明和主操作放在左侧 36%–42% 区域，不要把白色标题放到右侧灯光区域。
- `home-hero-wash` 只负责文字对比度，不要用不透明色块盖住整张图。
- 移动端继续使用现有的 `15-移动端诡镇奇谈竖版.avif`；42 是横版素材，不要在手机上强行裁成竖版。
- 如果最终选用 42，建议用 `v2` 文件名替换时保留 42 原图，便于回滚和 A/B 对照。

### 3.2 章节／新战役：`43-潮汐之门章节封面-v1.png`

对应代码入口：`frontend/src/arkham/views/NewCampaign.vue` 及其场景选择组件；故事开始前的章节封面也可复用。当前项目已有 `07-章节封面-潮汐之门.png`，43 是新的构图候选，适合需要更强“门／海／档案”叙事的场景。

推荐 DOM 结构：

```html
<article class="scenario-cover">
  <img
    class="scenario-cover__art"
    src="/assets/veiled-harbour/43-潮汐之门章节封面-v1.png"
    alt=""
    aria-hidden="true"
  />
  <div class="scenario-cover__content">
    <p class="archive-kicker">{{ chapterKicker }}</p>
    <h2>{{ chapterTitle }}</h2>
    <p>{{ chapterSummary }}</p>
  </div>
</article>
```

推荐样式：

```css
.scenario-cover {
  position: relative;
  aspect-ratio: 3 / 4;
  overflow: hidden;
  background: #26373a;
}

.scenario-cover__art {
  position: absolute;
  inset: 0;
  width: 100%;
  height: 100%;
  object-fit: cover;
}

.scenario-cover__content {
  position: absolute;
  inset: auto 10% 8%;
  color: var(--ink, #26373a);
  text-align: center;
}
```

使用规则：

- 保持 3:4 比例，最小显示宽度建议 180px；不要用固定高度压扁画面。
- 标题应放在下方档案页区域，避免覆盖石门、灯塔和罗盘。
- 图片 `alt` 保持为空，章节标题和摘要由真实文本提供；不要把章节名称写入图片。
- 章节卡的选中态仍由黄铜边线、阴影和文本状态表达，不给整张图片加霓虹光。

### 3.3 工作台／房间／牌桌外围：`44-午夜档案馆工作台-v1.png`

推荐候选入口：

- `frontend/src/views/Rooms.vue`：作为房间列表的深层背景或头部环境层。
- `frontend/src/arkham/views/Decks.vue`、`frontend/src/arkham/views/Deck.vue`：作为工作台环境，现有 `09-牌组工作台纸面.avif` 仍负责阅读表面。
- `frontend/src/arkham/components/Scenario.vue`：仅作为牌桌外围环境，不覆盖中央地图和卡牌信息。

推荐样式：

```css
.archive-workbench {
  background:
    linear-gradient(180deg, rgb(24 39 40 / 0.28), rgb(24 39 40 / 0.72)),
    url('/assets/veiled-harbour/44-午夜档案馆工作台-v1.png') center / cover no-repeat;
}
```

使用规则：

- 中央 55% 区域保持低对比，面板、卡牌和地图在其上方正常渲染。
- 如果同时使用 `02-牌桌材质`、`T01-调查地图底场` 或 `41-多人牌桌底场-v1`，44 只应作为最底层环境；三张完整场景图不要叠在同一层。
- 牌桌中央仍以信息可读性为第一优先，不能因为背景细节而降低卡牌数字、地点名称和行动按钮的对比度。
- 小屏不要只依赖 `background-position` 裁切；优先保留现有移动端牌桌竖版素材，或为移动端另做独立构图。

### 3.4 About／空状态／档案说明卡：`45-罗盘档案静物-v1.png`

推荐入口：

- `frontend/src/views/About.vue`：作为 About hero 右侧或赞助／社区说明卡的静物图。
- `frontend/src/views/Home.vue`：空档案状态旁边的 120–180px 视觉锚点。
- `frontend/src/arkham/views/Achievements.vue`、`CampaignLog.vue`：作为档案摘要卡的静态插图。

推荐使用方式：

```html
<img
  class="archive-still-life"
  src="/assets/veiled-harbour/45-罗盘档案静物-v1.png"
  alt=""
  aria-hidden="true"
/>
```

```css
.archive-still-life {
  display: block;
  width: clamp(120px, 18vw, 240px);
  aspect-ratio: 1;
  object-fit: cover;
  mix-blend-mode: multiply;
  opacity: 0.88;
}
```

注意：`mix-blend-mode: multiply` 只建议在象牙档案纸上使用；在深海底色上会变脏。若父容器是深色背景，应去掉该属性并改用 `opacity: 0.72`，或把静物图放在单独的象牙纸卡片内。

## 4. 组合规则

### 4.1 推荐层级

```text
页面结构底色
└── 场景环境图（42 / 44，二选一）
    └── 低强度渐变洗色层（仅保护文本）
        └── 纸面／牌面／地图／面板
            └── 黄铜边线、状态印章、DOM 文案
```

42 和 44 都是叙事场景，不要作为重复纹理平铺；C01–C03 才是可平铺材质。45 是独立静物，不要和场景图作为两层全屏背景叠加。

### 4.2 氛围控制

- 克苏鲁感来自雾、潮湿材质、不可解释的远景和旧档案语境，不依赖大面积触手、血迹、眼睛或怪物正脸。
- 古旧感来自磨损边缘、纸张、皮革、石材和黄铜的材质关系，不是把所有区域压暗。
- 典雅感来自留白、构图安全区和克制的黄铜亮点；交互控件必须保持安静、清楚、可读。
- 同一视图最多使用一个完整场景图；需要更多氛围时先调渐变和透明度，不要继续堆图。

## 5. 性能与资源建议

当前四张 PNG 作为源图保留，文件体积偏大，适合先用于开发与视觉验收。上线前建议：

1. 为 42、44 输出 WebP／AVIF 运行候选，并保留 PNG 源图。
2. 为 43、45 输出适合卡片宽度的 1×／2×版本，避免在小卡片中传输原始大图。
3. 使用 `<picture>` 或 CSS `image-set()` 提供现代格式回退。
4. 42 仅在首页首屏需要时预加载；43、44、45 不要加入全局预加载。
5. 场景图不参与 CSS 动画，不做持续缩放、呼吸或闪烁；只允许页面切换时的轻微淡入。

## 6. 视觉验收清单

- [ ] 首页桌面端 1440×900、1280×720：左侧标题和按钮清楚，42 的灯光没有压到文案。
- [ ] 移动端 390×844：仍使用独立竖版 Hero，不裁切 42 作为竖版背景。
- [ ] 新战役卡：43 保持 3:4，标题没有覆盖灯塔、罗盘和石门关键细节。
- [ ] 房间／工作台：44 的中央桌面不降低卡牌和面板对比度。
- [ ] About／空状态：45 作为完整图片使用，没有棋盘格、黑底假透明或脏污混合边缘。

- [ ] 图片失败时页面仍能显示完整标题、正文、按钮和辅助文本。
- [ ] 现代格式和原始 PNG 的裁切、焦点位置、暗部对比保持一致。

## 7. 生成记录

生成方式：Codex 内置 `image_gen`，按现有 `veiled-harbour` 视觉基线编写结构化提示词；未使用外部图片搜索或现有游戏卡面作为输入图。

提示词共性约束：

- 深海墨绿、蓝黑石板、象牙纸、旧黄铜、低饱和氧化棕；
- 1920 年代新英格兰海港／档案馆语境；
- painterly realism、premium tabletop board-game art、subtle print grain；
- 无文字、无 Logo、无水印、无现代物件；
- 克苏鲁氛围使用雾、远景和不可解释的建筑暗示，不使用怪物正脸和大面积血腥元素；
- 画面为 UI 预留安全区，文案由 DOM 叠加。

本轮已完成素材引用替换和局部背景分层，没有改变现有组件交互。仍建议在桌面端与移动端分别做一次视觉回归。

- 游戏工具条的幽灵按钮不加端帽：无框幽灵样式是既有定案，压饰只落在铭牌条这类静态条带上。
