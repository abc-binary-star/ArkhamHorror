## 2. 编译后的作用域语义（决定执行配方，已从构建产物核实）

```
源码  :deep(.card-frame)          →  产物  [data-v-069dd406] .card-frame
源码  .scenario-progress          →  产物  .scenario-progress[data-v-069dd406]
```

推论：

1. **`:deep()` 规则能扛住 template 抽取**：它只要求「祖先带本组件 scope id」，不要求目标元素自己带。子组件的根节点继承父组件 scope id，所以子组件内部的后代仍被命中。
2. **普通规则扛不住**：元素一旦搬进子组件模板，就不再带父组件 scope id，`.foo[data-v-父]` 立即失效。
3. 把普通规则改写成 `:deep()` 后，specificity 不变：`.foo[data-v-A]` 与 `[data-v-A] .foo` 都是 (0,2,0)。

## 4. 前置条件与顺序

`:deep()` 桌面版式的迁移**必须**排在 Player / Investigator / PlayerTabs 片段化之后：那些规则靠 `:deep()` 从外部给这些组件的内部定位，组件结构一变，规则的位置和内容都要跟着改，提前搬必然搬两遍。

推荐顺序：

1. **结构瘦身先做一个 slice 验证配方**——抽 `ScenarioPhases.vue`（阶段轨道，template 3415–3595），配 §5 配方，由用户在浏览器截图确认渲染无变化。
2. 配方验证通过后，继续抽其余自持区块。
3. 视觉 agent 完成 Player / Investigator / PlayerTabs 片段化。
4. 最后把 2,260 行 `:deep()` 版式按宿主组件搬到各自组件内。

## 5. 执行配方

抽一段 template 到子组件时：

1. 该段关联的**普通规则**：搬进子组件的 `<style scoped>`。选择器里的父组件前缀（如 `.scenario > .phases`）无法在子组件里表达，改写为子组件自己的根类（`.phases`）。specificity 不变。
2. 该段关联的**普通规则**若不搬（例如被父组件的布局条件约束）：改写成 `:deep()` 留在原处。specificity 不变。
3. 该段若被 `:deep()` 规则命中：**不动**。`:deep()` 规则在抽取后自动继续生效。
4. 媒体查询：随规则一起搬。搬后注意子组件的 CSS 与父组件 CSS 落在不同 chunk，**同权重规则的先后顺序可能改变**——这是唯一需要目视确认的点。

## 6. 验收要求

本仓库《游玩界面整体重构方案》§9 已写明「布局效果必须以真实浏览器截图和操作为证，静态检查不能替代」。结构瘦身无法自行完成这条，因此：

- 每个 slice 交付后由用户在真实浏览器回读对应区域并截图确认；
- 确认前不进入下一个 slice；
- 类型检查、构建、格式检查、已有测试是必要条件，不是充分条件。
