# 诡镇奇谈 · 地点地图层设计方案

日期：2026-09-10  
状态：P0 地图层已接入并完成浏览器验收，P1/P2 待做  
范围：牌桌中央地点区，不改变地点规则、连接关系、拖动和缩放行为

## 1. 结论

当前地点区的问题不是单纯的亮度不足，而是地点卡缺少地图节点、承托关系和清晰的路径层。卡片直接漂浮在深绿色纹理上，现有白色方块虚线又比卡片更抢眼，因此整体像调试画布，不像真实桌游。

推荐采用「深色牌桌 + 中央调查地图 + 地点节点底托 + 程序化路径」四层结构：

```text
外层牌桌：深海绿色织物 / 玩家区皮革
└─ 地图板：海港调查地图底板，四周有城市与海岸线，中心留白
   └─ 路径层：SVG 绘制的细黄铜虚线，位于卡片和人物棋子下方
      └─ 节点层：与地点网格对齐的黄铜定位环 / 虚线卡槽
         └─ 地点卡：真实卡图，带纸张边缘和轻微投影
```

这比继续加深绿色背景或给地点卡增加发光更有效，也能保留真实卡牌作为主角。

## 2. 当前问题证据

以用户提供的牌桌截图为准：

| 现象 | 根因 | 设计处理 |
| --- | --- | --- |
| 地点卡和背景对比不明确 | 中央地图没有可识别的地图层，纹理明度接近卡背 | 换成中心更可读、边缘有海港地图线稿的 T04 底板 |
| 卡片像漂浮在画布上 | 没有节点底托、格位或地图锚点 | 每个地点卡拥有独立的黄铜定位环和卡槽承托 |
| 白色方块连线很刺眼 | 当前路径的点划样式过粗、亮度过高 | 改为细黄铜虚线，增加低透明度深色描边 |
| 中央调查员与地点卡关系不清 | 人物头像和地点卡在同一层级，缺少棋子语义 | 调查员作为节点上的人物棋子/圆牌，卡片仍保持独立层级 |
| 四角地点显得过于分散 | 位置虽然来自网格，但没有视觉上的地图坐标感 | 显示浅色网格/节点锚点，不拉伸卡片填满空白 |

## 3. 视觉规范

### 3.1 地图板

- 使用 `T04-地点地图底板-v2.png` 作为第一候选底材。
- 底板采用 `cover`，允许裁切边缘，但不拉伸原始比例。
- 中心区域保持中明度深青绿，避免再叠加厚重的黑色渐变。
- 外围海港、海岸线和城市纹理只承担氛围，不代表真实规则路径。
- 底板边框不应压过地点卡；地图边框的明度约为卡片边框的 35–50%。
- 地图区与玩家区之间保留一条细黄铜分隔线，避免整张牌桌变成一块连续深绿色。

### 3.2 路径层

路径必须继续由 `Connections.vue` 的 SVG 动态计算，不把路线烘焙进背景图片。原因是地点支持拖动、缩放、剧本切换和特殊路线。

| 状态 | 样式 |
| --- | --- |
| 默认连接 | 1.5–2px，暗黄铜，虚线间隔 6–8px，透明度约 0.72 |
| 可移动路径 | 2–2.5px，暖黄铜，端点增加小圆点或短箭头 |
| 当前所在路径 | 默认路径上增加轻微局部亮度，不使用持续强发光 |
| 不可用/封闭 | 断开路径或使用小型封锁标记，不只依靠颜色 |
| 路径经过卡片 | 路径位于卡片下方，不能穿过卡面文字与规则区域 |

不再使用当前截图中的大块白色方形点划线。路径的存在感应当低于地点卡和可操作状态。

### 3.3 地点节点与卡槽

节点是程序层，不生成一张固定整图，以保证实际地点位置和视觉锚点永远一致。

- `.location-cell` 负责网格位置。
- `.location-wrapper` 增加节点承托层，尺寸比地点卡外扩 8–14px。
- 普通节点使用低透明度黄铜虚线框或双圆角线。
- 当前地点使用一圈较亮的黄铜细边和短暂的进入动画。
- 可移动地点使用清晰的焦点环，不能使用满屏紫色发光。
- 节点底托应有非常轻的纸张/绒面明度差，不能成为第二张卡。

推荐的节点层级：

```text
z-index 0：地图底板
z-index 1：网格辅助线与 SVG 路径
z-index 2：节点底托 / 黄铜定位环
z-index 3：地点卡
z-index 4：敌人、线索、调查员棋子和交互标记
```

### 3.4 调查员棋子

当前中央窄头像卡不适合承担地图棋子语义。建议拆成两种视图：

- 玩家区继续保留完整调查员档案卡。
- 地图区显示圆形或小型立柱式人物棋子，直径约为地点卡宽度的 28–36%。
- 棋子底部使用暗色投影和黄铜边，保证在路径交叉处仍能被识别。
- 多名调查员同地点时，采用扇形叠放或横向小组，不遮盖地点名称、线索和交互边框。

第一阶段可以先复用现有头像裁切和 CSS 圆牌，不急于生成固定人物棋子图片。

## 4. 布局与尺寸

以 1440×900 为主验收尺寸：

| 项目 | 目标 |
| --- | --- |
| 地点区可用高度 | 约 300–360px，视场景栏和玩家区动态分配 |
| 普通地点卡宽 | 100–120px；当前桌面截图中不低于 108px |
| 地点卡高 | 按原始卡牌比例自动计算，禁止变形 |
| 节点底托外扩 | 卡片四周 8–14px |
| 地点间最小可读间距 | 卡边之间至少 18px；路径可从中间通过 |
| 地图边距 | 16–28px，窄屏可降至 10–16px |
| 连接线宽度 | 默认 1.5–2px，可选状态最多 2.5px |

1366×768 时优先保持所有地点可定位，允许地图横向/纵向滚动；不要通过进一步缩小卡片来硬塞进视口。手机竖屏继续使用地图主视图和缩放控件。

## 5. 代码落点

现有实现已经提供了适合本方案的结构：

| 文件 | 计划 |
| --- | --- |
| `frontend/src/arkham/components/Scenario.vue` | 接入 T04 地图底板；增加地图板内框、节点底托和地图层级样式 |
| `frontend/src/arkham/components/Connections.vue` | 调整 SVG 路径颜色、线宽、虚线节奏和端点；保持动态测量逻辑 |
| `frontend/src/arkham/components/Location.vue` | 将普通/当前/可移动状态映射到节点和卡片外框，不改地点规则 |
| `frontend/src/arkham/cardImages.ts` | 不改真实卡图来源，仅保持原卡牌比例 |
| `frontend/public/assets/veiled-harbour/T04-地点地图底板-v2.png` | 新地图底板候选 |

现阶段不生成固定的“地点全图”或带地点名称的整张 PNG。地点名称、卡图、路线和数量都必须由真实游戏数据渲染。

## 7. 实施顺序

### P0：地图层原型

1. 将 T04 接入地点区，去除当前过重的深色遮罩。
2. 将路径改为细黄铜虚线，并统一路径下沉到卡片层之下。
3. 给每个地点增加节点底托和普通/当前/可移动三种状态。
4. 让中央调查员头像脱离地点卡边缘，先用 CSS 圆牌完成第一版棋子。

### P1：真实桌游质感

1. 调整地点卡投影、边距和节点锚点。
2. 多调查员同地点时做叠放和数量提示。
3. 为地点悬停、移动、当前地点和封闭路径补充一致的状态语言。
4. 在缩放和拖动后重新校验路径、节点和卡片没有错位。

### P2：剧本主题化

1. 为剧本增加可选地图底板配置，默认回退到 T04。
2. 对有真实地图的剧本接入独立地图素材。
3. 对特殊布局保留现有 `grid-area` 和拖动偏移，不把剧本位置写死在图片中。

## 8. 验收标准

- 地点卡与地图背景有明显的明度和边缘层级，但不依靠霓虹发光。
- 每张地点卡都能看出自己位于一个地图节点/卡槽上。
- 默认路径不再比地点卡更醒目；可移动路径仍能一眼识别。
- 路径不会穿过地点卡文字、线索和交互边框。
- 地图缩放、地点拖动、剧本切换后，路径与节点仍然对齐。
- 中央调查员能被识别为棋子，而不是另一张被遮住的地点卡。
- 1440×900、1366×768、1280×720 下地点名称、卡图和交互状态均无遮挡。
- 不使用固定整图承载地点名称、路线或游戏数值。
