# 诡镇奇谈 · 商业成品审查

审查日期：2026-09-09  
审查范围：首页、公共导航、牌组列表、牌组编辑、卡牌库、新战役向导、游戏牌桌、游戏日志、故事问题、选择弹窗、移动端适配。

## 结论

当前不是一部可以直接称为“商业成品”的完整 UI。它已经有清晰且有辨识度的视觉方向：首页、导航、牌组列表、牌桌背景和新战役背景已经形成「深海、档案纸、黄铜、诡镇奇谈」的品牌气质，概念层面达到可展示水平。

距离商业成品仍有明显差距：核心游戏操作界面仍混用旧的按钮、半透明黑盒、通用圆角和默认弹窗语言；故事问题、技能检定、卡牌库和牌组编辑还没有完全共用一套纸面组件；真实登录态、牌桌交互态和不同屏幕尺寸尚未完成视觉验收。第四波 HUD 素材已经接入，下一步需要把弹窗内层、卡牌交互反馈、移动端牌桌和空状态也收进同一套实体系统。

## 最明显的成品差距

### 1. 核心操作面板仍像功能组件

`StoryQuestion.vue` 中的 `.question-content`、`Question.vue` 中的 `.modal`／`.choices`、`ChoiceModal.vue` 的包装层仍依赖 `rgba(0,0,0,0.3)`、紫色按钮和较大的圆角。它们能工作，但没有和档案纸、黄铜边线、深海牌桌形成同一个物理世界。

第三波 `14-选择弹窗纸面.png` 已接入；第五波 `21-故事抉择内框.png` 现已作为 `ChoiceModal`、`Question`、`StoryQuestion` 的统一内层边框，下一步仍需通过真实视口检查标题区、正文区、选择区和危险操作区的密度与焦点状态。

### 2. 卡牌库与牌组编辑缺少“实体卡具”

当前牌组页已经有纸面背景，但卡牌区仍以旧的列表／图片容器为主，缺少卡槽边框、卡背、拖拽占位和选中态的统一材料。第三波 `13-卡槽纸面.png` 与 `16-卡牌背面纹章.png` 用于补齐这部分。

### 3. 移动端没有独立构图

首页在窄屏上把横向主视觉改为 `background-position` 裁切，仍然会损失诡镇奇谈的叙事和标题安全区。第三波 `15-移动端诡镇奇谈竖版.png` 应在 `max-width: 640px` 直接替代横向 hero。

### 4. 牌桌有背景，但还没有完整 HUD 语言

牌桌材质和侧栏已经建立了氛围；行动问题、技能检定、故事阅读和确认弹窗仍需通过真实视口做统一性验收。第四波 `17–20` 已接入 `GameLog`、`PlayerTabs`、游戏工具栏、错误纸面、断线提示和多人等待屏障。第五波 `21–24` 已补齐内框、卡牌交互横条、移动端牌桌和空档案状态，但还没有把操作按钮、行动托盘、侧栏抽屉和资源徽章收成完整的实体部件。

## 商业成品门槛

- 所有主要页面只使用一套纸面、牌桌、黄铜和深海状态语言。
- 故事问题、技能检定、确认、等待、错误、成功和危险操作都有明确且一致的层级。
- 卡牌的默认、悬浮、选中、拖拽、禁用和加载状态可一眼区分。
- 移动端拥有独立构图，不依赖桌面背景硬裁切。
- 真实登录态下完成首页、牌组、卡牌库、新战役、牌桌和回放的视觉验收。
- `prefers-reduced-motion`、键盘焦点、文字溢出和高缩放比例下仍保持信息层级。

本审查不改变游戏规则、API 或数据语义，只记录视觉完成度以及第五、六波素材接入情况。
