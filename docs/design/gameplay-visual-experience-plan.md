# 游玩视觉体验扩展方案

日期：2026-09-27。本次为代码现状盘点与方案，不实施游戏功能。

## 已有基础

现有组件提供了翻牌、阶段公告、强制效果说明、混乱标记变换、地图实体移动过渡、标记堆叠、洪水及附着状态表现。下一轮应优先补齐行动反馈与因果提示，在已有组件上增强，避免重复弹窗。

代码依据：`PoolItem.vue`、`TokenPool.vue`、`SkillTest.vue`、`ChaosTokenMorph.vue`、`ForcedEffectAnnouncement.vue`、`Location.vue`、`Scenario.vue`、`useCardFlip.ts`、`usePhaseAnnouncement.ts`、`AttachmentEffects.vue`。

## 第一批：每局都能感知的反馈

| 方案 | 画面表现 | 玩家价值 | 实现条件 |
|---|---|---|---|
| 1. 数值变化回执 | 资源、线索、伤害、恐惧旁短暂出现带图标的 +1 / −2，原数字轻微落定；单次约 600–900ms | 看懂哪张卡、哪个角色的数值变了 | 相邻已应用状态比较；首次载入、重连、回溯不播放；生命与理智要明确显示的是伤害/恐惧增加，不能把它画成生命恢复 |
| 2. 获得线索 | 地点上的小线索标记沿短弧线归入调查员线索池，地点留下一圈很淡的光 | 直接看见调查成果和归属 | 来源、目标确定时才连线；合并更新无法确认因果时，仅各自显示数值回执 |
| 3. 结算来源指引 | 当前来源卡边缘短亮；指向实际受影响卡的细线出现后淡去，必要时附一个效果图标 | 回答“为什么扣血”“哪个强制效果正在结算” | 结构化结算事件携带来源 ID、目标 ID、事件 ID；现有只有牌名的旧提示不能可靠定位同名实体 |
| 4. 移动路径与落点 | 延续现有实体移动过渡，额外短亮起点、路径和终点；到达后小幅落定 | 大地图中不易丢失调查员或敌人 | 单步邻接移动可由状态确认；多步路径、瞬移、交换位置需事件明确，不能根据最短路猜测 |
| 5. 回合与待操作对象 | 行动条上的一个行动符号被消耗后淡去；切换操作者时对应头像、页签短亮，显示稳定的操作者名字 | 一控多角色时更清楚“当前轮到谁”和“接下来操作谁” | 区分回合调查员、检定调查员、当前待答问题所属者；不能把技能协助误认为换回合 |

建议先做 1、4、5，再做 2、3。前一组依赖较少，后一组优先补足事件语义，避免动画演错。

## 第二批：关键行动更有仪式感

| 方案 | 画面表现 | 实现边界 |
|---|---|---|
| 6. 检定结果落印 | 在现有检定框中用小型旧金/暗红印记呈现成功或失败；旁边保留最终数值与难度，普通情况显示差值 | 只消费服务端判定结果；自动失败、平局失败等特殊规则不能仅用差值重算；祝福/诅咒继续抽取时不能提前播放结果 |
| 7. 敌人攻击与闪避 | 攻击者边框收紧，短线连接受击者；伤害分配完成后相应池反馈。成功闪避时敌人横置并浮现一次残影 | 区分攻击宣告、取消攻击、伤害分配及结算；不做全屏震动；不提前宣告伤害 |
| 8. 新地点揭示 | 在现有翻牌后，地点轮廓短亮，已公开连接线依次显现；地点名只在需要定位时短显 | 不暴露未公开地点信息，不提前移动视角；兼容不连通布局及特殊地图 |
| 9. 抽牌、打出与弃置 | 牌背从正确牌库移向手牌；打出牌移向实际区域；弃牌轻轻收向弃牌堆 | 只展示玩家有权看到的正面；一次多牌合并演示，避免逐张阻塞；接入真实区域变化，不能把检索当抽牌 |
| 10. 队友投入协助 | 投入区按调查员归组，投入时从该角色头像方向出现一条短细线 | 不透露其他玩家未投入的手牌；支持一控多角色和真实联机；取消投入后同步撤回 |

## 第三批：持续压力与章节变化

| 方案 | 画面表现 | 实现边界 |
|---|---|---|
| 11. 厄运临界提示 | 密谋厄运数字接近阈值时边框逐渐收紧，越过阈值时短亮一次；常态保持静止 | 使用实际总厄运与有效阈值。达到阈值不等于立即推进，不能显示“马上推进”或擅自触发翻牌 |
| 12. 危险生命/理智提示 | 头像或支援角落增加轻微裂纹，伤害/恐惧数字强调；治愈后消退 | 按实际生命/理智与可承受值判断，不能仅看印刷数值；不使用持续闪烁 |
| 13. 场景与密谋推进 | 加强已有堆叠转场：旧牌收下，新页展开，保留章节名与规则阅读时间 | 由真正推进事件驱动；不从牌号变化猜测；额外动画不再多加一层确认 |
| 14. 附着效果解除 | 锁扣松开、石块退散、雾气散去、蛛丝断裂；迁移则从旧卡淡出、在新卡形成 | 区分丢弃、失效、迁移及回溯；多个附着分别解除；离场残影最多约 450ms，不能继续表达规则仍生效 |

## 第四批：可选氛围

| 方案 | 画面表现 | 实现边界 |
|---|---|---|
| 15. 场景环境与昼夜 | 地图边缘的细雨、海底微粒、极地风雪；荆棘颜色随真实昼夜状态变化 | 环境由战役/场景状态确定，不能根据名称乱猜。昼夜可能受特定调查员或地点规则影响，需明确采用哪个视角的状态；不覆盖中央卡面 |
| 16. 冒险结束画面 | 结局正文出现前，一次简短的归档页转场；允许展示已确认的胜利点、创伤与关键记录 | 只展示结局完成后的最终结果，待选择或待结算时不预报。保持原结局文本的阅读与确认流程 |

## 共用视觉语言

- 旧金用于操作反馈与成果，灰绿用于环境与线索，暗红用于伤害/敌意，冷紫用于恐惧与异常；配合形状和图标，不只靠颜色。
- 反馈以发生位置为中心。屏幕中央留给正在阅读的牌、检定与必要决策，不增加装饰性口号。
- 动画路径与实体使用相同地图坐标；屏幕固定 UI 与地图之间的传递，需统一转换坐标并处理缩放、滚动和移动端布局。
- 频繁动作约 300–700ms；章节变化可稍长。动画通常不锁交互，输入可以提前收起；有规则先后关系的事件按现有消息队列处理。
- 同一时间一个主要提示。批量伤害以同一批次并行反馈，不排十几次动画。
- 提供“简洁 / 标准 / 氛围”三级体验选项。减少动态模式保留静态回执和明确文字；装饰层不截获点击。
- 所有事件去重；重连、载入存档、撤销、回溯时重建状态，不能把历史变化重新演一遍。

## 工程顺序

先为前端建立轻量的视觉事件队列，与规则结算队列分离；标记事件来源为状态差分或服务端明确事件。状态差分仅表达确定的最终变化，来源—目标关系不确定时降级为局部反馈。利用现有服务端事件时保留排序，并为新增因果事件提供唯一 ID。

第一批需要覆盖的自动检查：多角色定位、批量变化、重连与撤销静默、重复事件去重、缩放坐标，以及不改变任何原选项索引和点击行为。视觉验收待用户明确要求后进行。
