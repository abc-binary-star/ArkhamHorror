# 被动触发效果居中提示方案

## 交互规则

主动调查、攻击、闪避、移动、主动发动能力及普通快速行动维持原来的紫圈卡牌入口。

发动卡牌、受到攻击或其他游戏事件引出响应／强制效果时，在屏幕中央显示“有待处理的触发效果”。同一响应窗口的效果集中展示卡图和能力按钮；有能力说明时直接放在按钮上。服务端提供的上下文提示也会显示，不根据紫圈或游戏阶段猜测具体触发原因。

- 玩家点击一个效果，仍提交服务端选项的原始索引，不额外确认，也不自动发动。
- 同一时机的后续效果由服务端重新发问决定，弹窗随新问题更新。
- 只有服务端给出 SkipTriggersButton 才显示“跳过本次响应”。强制效果不添加跳过选项；静默自动结算的效果不制造多余弹窗。
- “查看牌桌”或 Escape 暂时收起窗口，屏幕下方保留“返回待处理效果”。收起不提交任何选择，不等于跳过。
- 技能检定中的响应同样弹出。普通检定、伤害／恐惧分配和目标选择保持原流程；响应发动后的支付、选目标问题回到既有组件。
- 只读取传入 playerId 对应的问题，沿用原来的多人座位权限及提交路径。

## 呈现与可用性

使用深绿底色、淡紫边线和象牙色文案，与紫圈能力入口呼应。桌面和手机均居中，长列表在窗口内滚动。卡图与效果按钮并列；同一卡牌的多个能力保留各自选项，不合并索引。无法解析卡图时仍显示能力按钮。

采用原生 dialog 的焦点约束和顶层显示，打开时隔离牌桌操作；可通过明确的“查看牌桌”收起。使用标题、说明关联，按钮最小高度 44px。提交时即时锁住弹窗按钮，共享处理状态完成后允许重试。问题被撤销或换成其他类型时移除弹窗。

## 实现范围

- `ChoiceModal.vue`：递归解开问题包装，识别解码器保留的 `ChooseOne.isWindow`，优先挂载响应弹窗。
- `TriggeredEffectModal.vue`：集中展示响应选项、服务端上下文、卡图、跳过入口，以及收起／恢复和防重复提交。
- 中英文 `base.json`：新增 `triggeredEffect` 文案。

后端已经用 `WindowChooseOne` 标识响应／强制窗口，用 `PlayerWindowChooseOne` 标识主动／快速行动窗口；前端解码时分别保留 `isWindow` 和 `isPlayerWindow`。此次直接使用现有契约，不改游戏规则和后端协议。
