# 阶段职责与客户端展示边界

按当前引擎的普通回合流程整理。卡牌、剧本效果可以插入效果或跳过步骤；不能为了减少弹窗改变这些响应窗口。这里的抽牌、资源等指阶段规则自动执行的效果，卡牌能力和调查行动仍可在各自合法时机产生同类效果。

| 阶段 | 顺序与职责 | 离开条件 |
| --- | --- | --- |
| 神话 | 阶段开始；在密谋上放置毁灭；检查毁灭阈值并结算推进；调查员依次抽取并结算遭遇牌；玩家窗口；阶段结束 | 遭遇揭示、衍生检定、强制效果和玩家选择处理完毕 |
| 调查 | 阶段开始及玩家窗口；选择调查员开始回合；各调查员执行行动及合法快速/响应能力；调查员回合结束；所有调查员完成后结束阶段 | 当前调查员的行动和回合结束响应完成，且无人尚待进行回合 |
| 敌人 | 阶段开始；猎手移动及相应效果；攻击前玩家窗口；敌人攻击、伤害/恐惧分配及相关响应；攻击后玩家窗口；阶段结束 | 攻击及衍生效果、分配与结束响应全部完成 |
| 补给 | 阶段开始及玩家窗口；4.2 重置调查员回合标记；4.3 重置横置卡；4.4 每位有效调查员抽 1 张牌、获得 1 资源；4.5 检查手牌上限并弃牌；4.6 阶段结束 | 抽到弱点等衍生效果、手牌上限选择和阶段结束响应全部完成 |

补给后处理轮末效果，再进入下一轮神话阶段。`BeginRoundWindow` 已设置神话阶段并执行轮初响应，因此阶段通知必须在该消息之前发出，不能等到后面的 `Begin MythosPhase`。按轮统计、下一轮行动额度等仍由 `BeginRound` 重置，不能混同于补给 4.2 的回合标记重置。

## 状态与展示协议

- 服务端在普通阶段切换时依次发送：上一阶段结束的 `PhaseSnapshot`、`PhaseChanged`、新阶段入口的 `PhaseSnapshot`。阶段快照清空问题，仅用于展示，不是可作答的持久化状态；最终 `GameUpdate` 提供可操作状态。
- 前端按同一个 FIFO 队列消费阶段通知、快照、揭示、日志、音效和最终状态。阶段横幅或揭示弹窗打开时暂停后续事件；解码及牌桌状态更新完成后才能处理下一条。
- 不得跨阶段使用“只保留最新状态”的合并策略。否则补给的抽牌/资源会提前出现在敌人横幅下，或者一直到神话阶段才首次出现。
- 补给抽到弱点时，先展示并处理此前的揭示，再播放下一阶段提示。阶段通知不能使用独立队列越过揭示。
- 快照不触发自动跳过响应或座位切换。撤销清理待播事件和阶段横幅，并使已开始解码的旧快照失效。
- 错误、联机共享状态和事件成员通知保留即时处理，以免被展示队列阻塞。

## 实现位置

- `backend/arkham-api/library/Arkham/Game/Runner.hs`：阶段步骤和后续阶段排队。
- `backend/arkham-api/library/Arkham/Helpers/Phases.hs`：敌人阶段。
- `backend/arkham-api/library/Arkham/Investigator/Runner.hs`：补给抽牌/资源、调查员回合标记。
- `backend/arkham-api/library/Api/Handler/Arkham/Games/Shared.hs`：阶段快照与通知。
- `frontend/src/arkham/views/Game.vue`、`frontend/src/arkham/composables/orderedGameEvents.ts`：顺序消费和状态应用。
